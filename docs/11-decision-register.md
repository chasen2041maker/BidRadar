## 4. 三项重点架构决策的取舍

**ADR-A：模块化单体，而不是起步微服务。**当前由一人独立实现，跨服务复杂性缺少必要性。保留 API/Worker 分进程能力，模块内接口清晰。代价是需要持续守住逻辑边界；若未来有独立团队或差异化扩展证据，再审拆分。状态 Proposed。

**ADR-B：数据库任务先行，Redis 后置。**目的是首先掌握已接受任务、事务、接管和结果发布。Redis 先作缓存，必要时可作唤醒/传输，但不再成为另一个业务真相。代价是需要关注数据库队列表负载与清理；真实瓶颈才推动迁移。状态 Proposed。

**ADR-C：证据状态优先于总分。**业务错把未知当满足的风险比界面没有一个漂亮分数更重要。硬条件、偏好和相关性分层；有用户校准再上权重。代价是用户需要读更多明确理由，应靠界面简化而非丢掉不确定性。状态 Proposed。

## 5. 风险登记

| 风险 | 影响 | 触发/验证 | 应对 |
| --- | --- | --- | --- |
| 官方入口可读但实际数据不够用 | 产品基础不成立 | 附件/关键字段/语种覆盖报告 | 缩范围或另审合法公开源，不用假数据遮掩 |
| 公开数据使用条件未完整核对 | 不适合公开分发/试用 | 法律页、附件条款及模型处理边界 | 先补审查，禁止自动公开原文全集 |
| 技术相关却无法参与项目 | 用户误解推荐 | 资格/地域/文件缺口人工审核 | 不给法律资格保证，单列未知与需人工项 |
| 用户只需关键词提醒 | Agent 复杂性无价值 | 对照 B0/B1/B2 的实际使用 | 保留简单流程，缩 Agent 工作范围 |
| 标段/版本错误关联 | 串用金额、日期和条件 | 多标段、错序、更正样本 | 原始引用、待关联、冲突状态、回归测试 |
| 私有资料通过缓存/图状态泄露 | 严重安全问题 | 跨空间、撤权、删除、恢复测试 | 阻止试用，修授权和派生数据撤回 |
| 提示注入或恶意外链 | 越权、外传或危险访问 | 安全样本与受控网络测试 | 工具白名单、采集器隔离、最小权限 |
| 重试导致重复提醒或费用 | 信任与成本受损 | 故障注入、状态对账 | 幂等发布、预算、外部不确定状态处理 |
| 为 JD 堆技术 | 本人无法掌握、业务迟迟不成立 | 每项基础设施是否有验收场景 | 后置、替代或取消非必要复杂性 |
| 生成代码多但本人没掌握 | 求职证据失真 | 独立修改与解释 | 关键链本人先写，记录真实贡献 |

概率与损失数值均未测，不用虚构风险百分比。
