## 5. 风险与处理

| 风险 | 观察信号 | 处理 |
| --- | --- | --- |
| 来源工作挤占产品 | 已能支撑研究仍不停新增连接器 | 无明确缺口就暂缓，优先完成用户任务 |
| 来源少但没有有用证据 | 全是历史或与软件无关 | 换/补有用源，不生成假项目 |
| Agent 只会摘要 | 无条件证据、追问和后续决定 | 按 17 走完一条核查与继续使用 |
| 数据脏与实现错误混淆 | 无原件或无规则版本 | 分 natural/parser/injected/replay 并保留前后对照 |
| 研究正确性不足 | 串标段、未知当满足、引用不支持 | 阻断发布、人工标签与固定回归 |
| 消息/任务恢复缺口 | 重复提醒、旧 Worker 覆盖、已发送消息丢失 | event_log/水位/Inbox/fencing，见 07/14 |
| 权限和版本最终一致 | 旧缓存或 checkpoint 暴露私有内容 | 当前授权、输入版本、撤权和后台委托测试 |
| 多服务运行超预算 | OOM、连接过多、固定费过高 | 资源账、错峰限额、重审而非静默追加 |
| 费用告警被当硬封顶 | 账单延迟、在途模型、出口增长 | 保守预留、停止新可变任务、留恢复储备 |
| 为展示牺牲真实能力 | 空服务多、关键逻辑全代写 | 个人逐任务实现、测试和解释 |
| 没有使用者价值 | 规则更省事、无再次使用 | 调整 Agent 职责，诚实标自用/原型 |
| 全球扩展误导 | 历史当实时、翻译当理解 | 按用途/语言/版本分级，不按地图宣传 |

原有微服务独立数据、禁止跨库、SSRF/恶意文件、备份还原和服务兼容风险仍按 04/07/14/15 验收，不因减少来源而消失。
