## 1. 状态规则

Confirmed requirement：用户已明确要求。Proposed：具体方案待审。Needs evidence：需来源或运行证据。Accepted：必须有负责人明确批准。Superseded：已被新要求/决策替代。Deferred：后置范围应记录理由及批准。

用户批准方向不等于批准全部细节；AI 不代签实施授权、评测结果、用户数量、部署完成或购买确认。

## 5. 保留的服务拆分约束

六服务为了独立数据、安全、CPU/I/O/配额与持续任务责任；代价是网络故障、契约兼容、最终一致、授权与运行成本。同机器部署仍保持接口和数据边界，但不证明多节点高可用。预算低不能用跨库共享超级账号规避实现责任。

## 6. 风险与对策

| 风险 | 触发证据 | 对策 |
| --- | --- | --- |
| 有入口但不许可/不可访问 | 403、身份限制、附件权限、条款不清 | 不绕过，保留受阻，另源同样准入 |
| 全球来源只是大量历史资料 | 活跃机会比例不足 | 活跃/历史分报，不让地图替代覆盖证据 |
| 地区/语种扩大导致误判 | 否定词、金额或状态错误 | 原文定位、分语言留出集、未支持即标记 |
| 网页日期/状态语义串用 | 表头/章节与提取字段不符 | 保存作用范围和原始证据 |
| 微服务成为共享库单体 | 跨库、共享 ORM、长同步链 | 账号拒绝测试、契约测试 |
| Redis 已发送消息丢失 | 清空 broker 后消费缺口 | event_log/水位补投、超窗快照 |
| 陈旧索引/档案/授权 | 新版或撤权到达不齐 | 冻结输入、as_of、私有读当前授权 |
| 多源超出时间 | 申请身份、语种标注、规则工时增长 | 阶段交付，重估区域增量，不牺牲 Agent 评测 |
| 报价不满足预算 | 续费、地域、云盘/网络超过额度 | 不下单，重审配置/运行时间，不暗增支出 |
| 单机资源挤占 | OOM、DB连接多、队列老化 | 有界进程池、错峰、配额，保留资源余量 |
| 可变费用失控 | 模型重试/长上下文/下载/日志增长 | 保守预留、调用上限、保留期限及停新任务 |
| 节省成本牺牲恢复 | 备份只在同盘、原件过早删 | 独立备份、还原验证，不能因超额清业务数据 |
| 自然脏数据名不副实 | 无原件只有造错 | 自然/解析缺陷/注入分开 |
| 未授权付费/外发 | 需要 Key、机器或通知 | 单独批准，不因预算已给就创建资源 |
