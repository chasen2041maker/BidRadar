## 3. 审核关口

| 关口 | 通过依据 | 当前 |
| --- | --- | --- |
| G0 产品 | 首用户、典型任务、输出和非目标能说清 | 待审核 |
| G1 支撑数据 | 首个有用来源的访问/使用边界、原文、状态及材料缺口已验证 | 待授权验证，不要求四源/六源 |
| G2 服务与状态 | 数据所有权、任务、消息、档案、报告和跟踪的生命周期可走查 | 待审核 |
| G3 质量和成本 | 基线、错误案例、权限、恢复、月预算与费用控制可验证 | 待审核 |
| G4 有限实施 | 本次任务及本人职责明确，负责人批准对应范围 | 未授权 |

只验证一个样本时，不必先买服务器或证明全部容量。私有资料进入共享环境前，权限和数据处理边界必须先通过。

## 4. 同一个产品案例贯穿审核

虚构案例：一家做知识库的软件团队，不接受长期驻场；候选项目有两个标段。

从建立确认档案开始走：项目列表是否相关且有同步时间；某标段驻场条件未知时怎样显示；Agent 引用能否打开到原文；追问能否保持标段与企业版本；用户放弃、收藏和停止跟踪是否分别保存；一份更正只改一个标段时如何复核；重复事件会否重复提醒；报告生成时取消、预算不足或权限撤销如何处理。

每一步先解释使用者看到什么，再指出服务、事务和验收证据。说不清楚就修设计，不用新增来源或框架替代答案。

## 6. 当前优先审什么

先审报告是否帮助决定下一步、追问与记忆是否有用、变化提醒是否能持续使用、任务失败是否可解释。再审六服务与低预算运行的实现成本。

来源扩展的审核问题是“当前哪个工作因数据缺口做不成”，不是“还缺哪个洲”。全球能力继续保留，但不能挤掉产品、Agent 评测和本人实现。
