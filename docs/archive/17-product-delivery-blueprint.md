# 17｜产品交付蓝图：先把一件业务做完整

**v0.4｜2026-09-15｜SOURCE-001两阶段流程确认；设计不等于全链实现。**

本页同步01和28：负责人明确要求加入“采集→awaiting_decision等待选择→选中项目AI分析”及本轮借鉴点。既有公司隔离、三角色和小步执行按26/27，代替旧版尚未讨论角色或必须本人先手写的表述。当前实现状态只看PROJECT_STATE及PR。

## 1. 产品定位与输出

交付可保存、可追问、可复核的商机研究档案：原始材料清单、条件证据表、企业能力对照、未决问题、人工决定和变化历史。目录回答“哪些值得打开”，深度分析回答“这个项目到底适不适合我们”。价值需实际用户与人工/规则基线对照验证。

虚构场景：一家做后端、知识库和AI应用的公司，不接受长期驻场；资质按实际提供材料确认，不预填。以下为目标流程，不是假装已有真实客户或完整运行界面。

## 2. 首个使用场景

| 步骤 | 用户动作 | 产品交付与约束 | 主要服务 |
| --- | --- | --- | --- |
| 1 | 确认企业档案 | 区分事实、证明、偏好和硬限制，保存版本 | workspace |
| 2 | 搜索/筛选候选 | 类型、时间/金额口径、已知相关性、来源新鲜度和覆盖范围 | catalog |
| 3 | 打开详情与材料 | 原链接、所属程序/标段、已取/未取材料；不自动启动新分析 | catalog / processing |
| 4 | 在awaiting_decision中勾选并确认 | 明确固定项目/标段ID及版本，空选择不提交；显示范围与费用边界 | workspace |
| 5 | 请求深度分析 | 重新校验当前权限、资料许可和额度，先持久化，再返回任务ID | research |
| 6 | 查看分析或追问 | 条件—证据—企业资料—五状态—缺口；保持项目和输入版本 | research |
| 7 | 记录跟进/放弃 | 人工决定、原因、并发版本和修改历史；不是资格认证 | tracking |
| 8 | 单独开启/关闭跟踪 | 关注对象、变化范围、是否授权自动复核；关闭不删历史 | tracking |
| 9 | 新材料或更正出现 | 哪条事实改变、哪些结论陈旧、下一步补证/复核 | catalog / research / tracking |

ingestion和processing提供获准公开资料及可追溯证据。公共采集不随某家公司等待选择而挂起；用户选择不是模型审批投标决定。其他来源只在某一步出现实际证据缺口时增加优先级。

## 3. 两阶段交互契约

阶段A默认只用目录查询、规则和已有索引做候选筛选；列表翻页、打开详情、刷新页面、查看已保存报告不隐式重跑模型。后续如需轻量模型排序，必须单独约定成本与收益，不由本次默认启用。

awaiting_decision属于公司私有选择会话（workspace拥有），不是analysis_run状态，也不是锁住Worker等用户点击。选择快照保存固定ID/版本和会话并发版本，具体持久化/HTTP契约在实现前按14登记。前端不能只提交数组下标、角色或自报公司作为授权依据。

空集合拒绝；缺省选择不得等同全选。显式全选也要确认范围、数量和额度。提交前重验权限、输入可见性、来源/项目当前性、档案版本和预算；关键版本变化让用户重新确认，不把新数据静默塞进旧选择。重复幂等请求返回原任务，同键异内容冲突；网络失败不能自动换键重建任务。

从阶段A进入阶段B，只能由用户明确确认或独立存在的有效跟踪复核委托触发。后者不能因收藏或阅读报告自动取得；每次复核仍受当前权限、输入范围和额度约束。

## 4. 一份合格分析报告

| 区块 | 必须解释 |
| --- | --- |
| 身份与版本 | 程序/标段、目录/文档/解析版本、企业档案/偏好版本、模型/规则配置、分析时间 |
| 范围与材料 | 实际读取、未取得、解析失败、过期/受限资料分别列出；来源检查与最近成功同步时间 |
| 简要判断 | 值得核查/明确不匹配或冲突/资料待补充；不以一个分数掩盖硬条件未知 |
| 条件证据表 | 要求原文、位置、所属范围、企业证据、五状态、理由、支持及反证 |
| 待确认问题 | 缺什么、由谁确认、补哪项证明或从哪个获准来源补证 |
| 下一步 | 继续核查、补证、人工跟进/放弃；不自动联系采购方或提交投标 |
| 历史与费用 | 与前次输入差异、当前性、任务结果、模型/用量/费用已知和未知范围 |

五状态沿用05：met、unmet、unknown、conflicting、not_applicable。没有企业资质资料不是unmet；没有完整附件不得说全部要求满足。引用可打开不等于支持陈述，须回核具体原文版本、标段、位置和当前权限。

借鉴bid-intelligence的清单与澄清问题，不复制管道检测字段、个人路径或固定条款；不用未经自有评测的0.85阈值宣布可信。可导出的清单是后续交付形式，不在本轮新增Excel模块。

## 5. Agent、记忆与人工决定

程序负责过滤、日期/金额语义、去重、权限、参数、预算与发布；一个有界主编排器选择当前授权范围内的只读工具，整理要求、引用和缺口。微服务数不等于Agent数，多Agent需评测收益，不为形式预建专家聊天。

研究取不可变输入manifest。后续新材料只有明确补证/新分析才进入；旧报告不被静默改写。模型前次结论不是新的原始证据，跨项目提问必须明确切换范围。

workspace拥有确认事实/偏好及选择会话；research保存分析、checkpoint和问题；tracking保存人工决定、关注与提醒。不把“可能有资质”记为确认事实，不把一次放弃永久当作行业禁入。普通共享与受限资源按27，平台/CMS管理员不自动有权。

人工Review decision和Watch独立。needs_review/follow_up/dismissed、expected_version、reason、actor及依据引用继续是接口提案，动工前统一到14的契约；本轮不改已有事件枚举。

## 6. 失败也要有明确产品输出

| 情况 | 用户看到什么 | 禁止行为 |
| --- | --- | --- |
| 来源失败/受限 | 哪个来源失败、范围、检查时间、最近成功同步；可标partial/degraded | 假装全站没有商机或全部已读 |
| 真正零结果 | 在成功且可解释的查询范围内零匹配 | 与超时/验证码/DOM改变混为一谈 |
| 无选项/版本已变 | 不建任务，提示选择或重新确认 | 缺省分析全部、悄悄换新版本 |
| 重复提交/刷新/断网 | 原持久任务和已有结果可继续查看 | 重复建费任务、丢失已接受请求 |
| 工具/模型失败 | 明确未完成/部分结果及有限重试；保留目录和已有有效报告 | 未评分等同不相关、伪造完整结论 |
| 取消 | 持久取消状态、停止新外部动作、在途费用限制 | 关闭窗口就声称所有外部调用已撤回 |
| 额度不足 | 明确暂停/拒绝原因，已有可读资料不受影响 | 换更贵模型、假装无商机 |
| 档案/材料更正 | 新旧版本与受影响条目，标记待复核 | 用旧报告冒充当前判断 |
| 撤权 | 私有读取拒绝，下一后台动作重验委托 | 旧缓存/checkpoint绕过当前授权 |
| 解析修复 | 新派生版本和质量原因 | 改原件来掩盖旧错误 |

来源请求full只表示本次请求的来源未报告失败，不表示全国完整覆盖；时间戳不能只剩一个TTL。UI文案不私自创造任务终态，预算暂停等先按原因或调度状态建模，HTTP/事件设计仍按14统一。

## 7. 跟踪与提醒

先对已关注对象做版本差异和影响定位。截止、资格、交付条件、预算口径、附件或业务状态变化可能触发复核；纯排版变化不自动重跑昂贵模型。原公告/更正关系要有依据，不能只靠相似标题；变更发生在一个标段时不扩大到其他标段。

新变化先使相关结论陈旧。有效授权允许的自动复核才新建research任务，否则提醒用户确认；重复事件按关注对象、规则版本、变化指纹与提醒类型去重。首次目录筛选的人工选择与后续自动委托不是同一权限。

P1应用内提醒优先。未来邮件/短信以每渠道独立attempt和成功状态记录，不能用一个共享success标记全渠道已送达；内部唯一提醒也不保证第三方投递恰好一次。

## 8. 数据最低要求与验收包

先人工核查约10个代表项目，再设计30–50个任务案例，均是工作量提案不是已有样本量或硬发布门槛。包含相关/不相关、历史、当前性不明、更正、附件缺失和来源失败；暂无自然变化可使用获准历史版本回放，明确不是真实时同步。

| ID | 验收场景 | 证据要求 |
| --- | --- | --- |
| BP01 | 建档后找到候选 | 档案版本、查询范围、原链接、新鲜度、公告阶段 |
| BP02 | 资质/附件不足仍有限分析 | 五状态、未知原因，没有越界结论 |
| BP03 | 同项目追问后刷新/重登 | 项目/标段/版本、持久任务与未决问题 |
| BP04 | 人工决定与跟踪开关分别修改 | 授权、并发版本、幂等及历史 |
| BP05 | 单标段变化和重复事件 | 前后证据、影响范围、内部唯一提醒 |
| BP06 | 取消、超时、额度不足 | 状态、重试上限、调用/用量未知范围 |
| BP07 | 档案变更与撤权 | 新旧输入界限、拒绝旧私有访问 |
| BP08 | 人工/规则/Agent配对基线 | 相同资料、标签、漏项、修改、耗时和费用 |
| BP09 | 真实网页/文件清洗 | 原件、解析版本、前后对照与回归 |
| BP10 | 云端独立升级和恢复 | 镜像/配置、日志、还原验证与环境限制 |
| BP11 | 浏览/翻页/打开/刷新 | 未发生隐式新分析或新模型调用 |
| BP12 | 空选择、重复确认、选择过期 | 不分析全部；同键同任务；同键异内容冲突；过期重确认 |
| BP13 | 来源错误与模型失败 | 错误不等于无结果；目录和有效历史报告仍可读取 |
| BP14 | 自动复核的授权边界 | 无有效委托不调模型；撤权/取消/额度变化阻断下一动作 |

离线HTML适配测试、持久任务/HTTP集成、真实模型、实时同步、云运行和受控试用分别验收。本轮仅完成其中一个离线小片；BP11–14是新增后续验收要求，不能拿解析测试替代。
