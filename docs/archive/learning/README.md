# 学习记录与自动记忆

## 这三种文件不要混淆

任务笔记是长期知识，由执行任务的 Codex 基于实际变更/证据维护；INDEX.md 是脚本生成的可重建目录；[Issue #4](https://github.com/chasen2041maker/BidRadar/issues/4)是 main push 自动更新的动态快照。源记录在 Git 历史中，运行日志保留期受 GitHub 配置约束，不以日志永久存在为前提。

Skill 负责从本次工作提炼有用内容，脚本不理解聊天、不猜业务完成。主分支快照只给 main 工作流写；未合并分支状态留在其 Actions summary，不污染主线。不自动合并、不创建定时模型调用、不从任意外部文本执行命令。

## 每个任务一份笔记

文件名如 DOC-004.md 或 CMS-001.md，用编号补足三位并尽量按任务序列分配。索引按文件名倒序展示最多 20 条，运行摘要最多 5 条，不表示跨前缀的时间顺序；全部源文件仍保留。过长笔记另拆专题并链接，不删有价值的历史。

必须有首行标题、唯一的 1–200 字单行 `摘要：` 和以下六个非空章节。这个格式是项目约定，不是通用 Markdown 语法；章节名不要放进示例代码块冒充真实内容。

## 本次改变

写范围和真实改变，不把提案当已实现。轻微格式改动沿用任务笔记说明无新知识及原因，不反复复制聊天。

## 阅读顺序

给 1–3 个文件+符号、阅读顺序和为什么读；一条问题只拆必要代码。

## 数据流与失败边界

解释输入到输出；指出版本、权限、缓存、异常的关键约束；描述注释与测试的对应关系。

## 验证与未验证

记录命令、退出码、环境、SHA 和证据位置。尚未执行的项目写原因/补测条件；历史 SHA 的成功不是当前 head 的成功。

## 我的参与

默认待阅读/待实践；用户确认后分别记录读过、修改过、运行过、能解释。标记依据来自用户反馈或明确操作证据，不由 AI 自己宣布用户学会。

## 值得保留的决定与坑

保留确认决定、实现原因、失败原因、修复思路和可复用边界，附来源与替代关系。

## 刷新与检查

编辑状态/任务笔记后运行 `python3 scripts/refresh_project_memory.py --write`；CI 用 `--check` 防索引陈旧，用 `--base <SHA>` 防变更漏笔记。只检查记录存在和格式，不证明内容充分或中文注释正确；这些由独立审查检查。

GitHub main 发布器只能更新固定 Issue #4，使用最小 issues:write；不持久保存令牌、不改 main、不重开关闭页。工作流串行发布，先核对远端 SHA 跳过过时任务；存在正常的事件/排队延迟，快照始终标明对应提交，不承诺瞬时强一致。
