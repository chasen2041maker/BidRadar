# 03｜数据基础：优先满足产品的证据需求 v0.3

**Proposed｜2026-09-11。未运行连接器，未建立真实 API 字段映射。本轮不重新核验外部来源。**

## 1. 目标与优先级

前期建议一个主来源、按需第二来源。取消四源/六源/六大区验收门槛：数据首先支撑发现、分析、追问和跟踪，而非独立追求覆盖数量。全球池保留在 16；真实网页和文件处理仍属于完整 v1 的能力，但不阻塞首个有证据的研究版本。

| 证据层级 | 能证明什么 | 当前 |
| --- | --- | --- |
| 来源说明/网页 | 存在入口或某类内容 | 继承历史阅读记录，不是新验证 |
| 运行访问 | 本机能请求、下载并遵守访问条件 | 未测 |
| 业务适用 | 能获取与软件/AI 项目有关的证据、状态及标识 | 未完成抽样 |
| 正确接入 | 幂等、清洗、版本、隔离与回放成立 | 未实现 |
| 用户价值 | 减少核查劳动或避免遗漏 | 未验证 |

入口可读不能推导后四层通过。缺少授权或可靠原文时不能用模型补齐“真实数据”。

## 2. 从用户工作倒推数据

| 用户工作 | 需要的资料 | 资料缺失时 |
| --- | --- | --- |
| 找相关项目 | 稳定来源身份、服务范围、分类/标题/正文、类型与状态依据 | 无法确认当前性时独立标未知，不冒充开放项目 |
| 判断是否适合 | 原文条件、标段范围、用户确认的能力、已知日期/金额及其含义 | 未披露不填零、不猜资格；给待确认项 |
| 回答追问 | 可定位正文、材料清单与版本、已知未决问题 | 有限补证；无法取得就说明 |
| 保存与继续研究 | 输入 manifest、档案版本、报告、人工决定 | 保存失败不显示成功 |
| 跟踪变化 | 源 ID/修订引用、前后原文、字段范围、获取时间 | 关系不明确不强合并；历史回放与实时验证分开 |

稳定身份和可追溯原文是可信分析基础。金额、资质或时区不是必须全部非空；允许缺失，但必须表达缺失的原因和影响。

## 3. 首来源选择及候选池

首来源按业务相关性、原文定位、状态语义、版本线索、允许使用范围、网络访问和语种可评测性选择。TED 是原有候选，不是已经批准或接通的固定方案；原文/附件可用性仍需验证。

第二来源只有在补当前机会、缺失材料、重要格式/语义、可靠更新或明确用户需求时进入。一个发布者的 API、XML、HTML 和附件算一个独立来源，仍可提供多种处理路径。

既有候选及历史状态：TED 查询文档已读但未 POST；CanadaBuys 早前目录可读、后次重读 403；GLD XML 仅资源说明；香港两个网页有状态/日期语义观察；BOAMP 未取得完整 schema/记录；英国部分入口受阻。均以 [12](12-source-register.md)、[13](13-source-matrix-and-dirty-data.md)、[16](16-global-sources-cloud-budget.md) 的时间记录为准，不在本轮升级状态。

## 4. 分层与所有权

Raw 由 ingestion 拥有：source/native ID、请求窗口、获取时间、媒体类型、字节哈希、原件引用和使用边界。哈希标识字节，不证明事实正确。

Normalized 由 processing 拥有：原文/规范字段、段落和证据位置、解析器与清洗规则版本、错误和隔离。输出某来源的一次观察，不强认跨源同一程序。

Canonical 由 catalog 拥有：程序/标段/公告族关联、冲突、版本投影和搜索索引。引用依据优先，内部标准化不修改原始公告。

Derived 由所属服务拥有：research 的要求解释、匹配报告和快照不是来源事实；tracking 的人工决定和提醒不是官方状态。派生索引可重建，私有档案权威仍在 workspace。

各层通过契约和事件传播，不跨库写表；新解析生成新版本，保留历史证据。

## 5. 采集与增量

优先使用适合的官方入口，需要正文/附件时按登记域定向获取。连接器是 ingestion 内的适配器，不是一源一服务，也不是任意 URL 代理。

每源登记 discover/fetch/checkpoint、身份、速率、robots、保存/模型处理/展示/分发边界。robots 不替代使用授权；不绕过验证码、登录或付费墙。SSRF、DNS/重定向和文件安全见 07。

API 保存查询指纹、时间窗、游标、原页和条目状态；不假设分页天然同一快照。必要时重叠窗口与回查，幂等处理。

CSV/XML 是文件快照：相同哈希可跳过重解析但保留观察时间；新字节保留原件。条目未出现在当日文件不自动等于取消。

HTML 保存章节、表头、原文和结构版本；访问验证页、动态占位或解析失败不能作为零条成功。混合历史/新信息时按语义分开。

仅当窗口内条目已持久保存或明确隔离且可追查，才推进水位。抓取完成、解析完成、入目录、被索引和分析完成各自有状态。

## 6. 真实脏数据与实现错误

natural_observation：来源中的真实缺失、冲突、重复或语义陷阱，保留原件依据。

parser_defect：原件正常，但我们丢表头、否定词或作用域，属于实现缺陷。

injected_case：在获准副本中制造坏字段、乱码、乱序等，用于确定性防御测试。

amplified_replay：用于负载的扩增记录，不是独立真实商机。四者分开统计，不能把人工删值包装成天然脏数据。

## 7. 质量与字段规则

| 类别 | 处理要求 | 禁止 |
| --- | --- | --- |
| 金额 | 原值、Decimal、币种、税/期间、预算/授标及标段范围 | 空值变零、跨币种相加、总预算复制到每标段 |
| 日期 | 原文、角色、精度、时区证据、可确定的标准时间 | 第一个日期当截止，未知时区默认 UTC |
| 状态 | 分节、公告类型、字段角色与正文依据 | Open 采购方式当开放状态，授标当可投 |
| 文本 | 保留标题、段落、表头、否定、脚注和单位 | 正则删掉限定条件或只交标题给模型猜 |
| 身份 | source namespace+native ID，明确修订/引用优先 | 标题相似强合并、局部标段号全库唯一 |
| 重复 | 原件、转载、语言和修订分开处理 | 去重后删掉全部来源关系 |
| 语言 | 原文与译文版本、归档/检索/分析支持分开 | 未评测语言给确定性全面判断 |
| 空值 | missing/parse_error/inaccessible/conflicting/not_applicable | 用空字符串掩盖不同原因 |

疑似来源笔误保留原值，另记候选修正和人工依据，不静默“纠正”官方事实。

## 8. 隔离、重处理和安全

quarantine 保存错误、原件、规则/解析器版本、尝试、责任阶段和复核状态。可恢复失败与不支持分开；修复后选择性重处理，产生新 document_version，经 catalog 发布修订，使受影响报告待复核。

处理计数须互斥：normalized、partial、quarantined、skipped_known_duplicate 等，定义后冻结；输入总数和排除原因可对账。

XML 保留路径/命名空间，禁外部实体；HTML 展示去执行能力；PDF 优先原生文本并保留页码；Word 不运行宏。限制下载/解压字节、页数、CPU/内存和耗时。扫描件先标 image_only/needs_review，OCR 仅有业务需要且经过费用、质量审核时进入。

## 9. 初始数据验收

建议少量原始记录即可启动人工走查，例如约 10 个不同情况的项目；覆盖相关/不相关、开放/结束、缺失材料/多标段等，不要求每源先积累一大批。

R0 检查稳定标识、真实原文、状态/日期语义、重复处理和证据定位；R1 支撑完整研究；R2 前补齐真实 HTML 和文件链及一项前后对照回归。来源多少不影响上述标准。

没有自然变更时可用获准历史版本验证机制，报告标回放；实时同步仍须单独验证。评测按公告族及已知转载/变更关系分组，避免同项目同时进入开发与留出；难例和无法获取项不悄悄剔除。

## 10. 使用与撤回

每源分别审核采集、保存、模型处理、展示、再分发和删除范围；开放目录不覆盖所有外链附件。公开仓库只存允许的代码/小样本/元数据，不存联系人全集、企业私有资料或未经审查文件。

源撤回、许可变化或私有删除应使索引/缓存/报告访问收敛失效，tombstone 参与重放。说明备份保留和到期删除边界，不承诺瞬时抹除所有历史副本。

全球目录是后备资料，不是待全量抓取队列。新增来源要说明填补哪项业务缺口，不能延后产品和质量验收。
