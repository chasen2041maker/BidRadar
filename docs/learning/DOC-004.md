## 数据流与失败边界

一次有效变更 → Codex 根据证据更新短状态和任务笔记 → 生成确定性索引 → 推送/PR 触发 CI 检查 → 合并 main 后把真实 SHA 与检查 outcome 写入 Issue #4。

源记录是权威输入，索引是派生结果；分支运行摘要与 main 固定页分开。流水线失败如实显示失败/跳过，不从有代码推断通过。过时 main 发布任务跳过；固定页关闭或缺标记时停止覆盖；权限只给 main 发布任务，不让 PR 内容取得写令牌。

## 值得保留的决定与坑

Skill 是主动工作流程，不是永远运行的进程；允许隐式调用也不保证宿主已发现。真正自动发生的推送/合并检查和固定页刷新由 GitHub Actions 实现。

自动化只汇总已记录事实，不替人编业务决定、不把测试绿灯当作本人学会。正文状态和学习程度分开；重复的小修复更新同一任务笔记，避免把记忆写成无穷聊天日志。
