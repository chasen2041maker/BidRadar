## 2. 任务开始与接口

先读项目与相关代码，明确需求范围、主要流程、验收、依赖、风险和回退。能由现有约定解决的技术细节不重复询问；业务含义、授权或关键条件缺失才向负责人确认。任务授权内的跨模块修改直接执行并记录影响，不以“不是本模块”为由停工。

前后端先约定路径/方法、字段类型、必填/空值、返回体、错误码和鉴权。分页的游标/页码与排序、时间的语义/时区、金额币种/精度、状态枚举和转换、版本冲突/幂等分别写清。变更与受影响方确认；不兼容变更给旧客户端、事件消费者、数据迁移和切换方案。

交付状态分别记录：契约已确认、模拟数据可用、真实接口可联调、端到端已验证；不得合并成一个“完成”。模拟可以支持并行开发，但不证明真实链路可用。

## 3. 自测、联调与证据

后端先在约定环境验证正常、异常输入、鉴权、边界、数据写入和状态转换，不能只看 HTTP 200。回调、消费、定时任务用可控事件触发；重试/重复投递核对真实数据、费用和副作用没有重复。缓存验证命中、更新、撤下、撤权、旧请求晚回填和故障回源，不只测延迟。

前端验证页面、交互和受影响旧功能，覆盖加载、空数据、错误、网络中断、登录过期、权限不足、重复点击与取消。涉及后端就记录实际接口版本和联调范围；UI/交互改动附对应设备、系统、浏览器及脱敏截图/录屏。中文输入法与报错在 22 中作为具体门槛。

第三方条件不足时先验证可控部分，记录未验证部分、阻塞原因、负责人和补测条件。只交付已经验证的范围，不伪装完整验收。交付提供接口文档、环境/版本、可复现请求、测试记录、已知问题；“本地正常”不是结束联调排查的依据。

每条验证至少记录：

```text
任务/PR：
被测提交 SHA（最终版本）：
时间、工作目录、环境/依赖版本：
实际命令/输入：
退出码与观察到的数据/业务结果：
证据位置（脱敏日志、截图或 CI run）：
层级：静态 / 离线 / 模拟 / 真实集成 / 受控生产
未执行项、原因、负责人、补测条件：
```

日志不嵌入密钥、令牌、企业附件或原始私有提示词。没有运行的命令只能列“待执行”；文档工具测试不能写成产品测试。验证后又改了实质内容，重新验证最终提交，不能沿用旧 SHA 成绩。

## 4. 分支、差异与独立审查

独立任务分支与并行独立工作树；不得直接在 main/发布分支开发、强推、覆盖他人改动或绕过保护。隔离目录之外还要检查端口、环境变量、数据库/缓存、账号、外部服务和费用，测试不能误打共享或生产环境。

提交按任务集中，不混无关重构、格式化、临时文件或调试凭据。提交说明关联任务、目的和影响；检查实际差异，可提前推送协作但不未经授权触发生产。

独立审查由另一位审核者或独立 Codex 审查任务执行，不能仅使用实施会话自评。审查记录须绑定最终提交及范围；P0=可能造成重大数据/安全/不可逆影响的阻断，P1=影响主要正确性或关键规则的阻断，与产品阶段优先级不同。发现阻塞必须修复并复核；实质追加改动重新审查。

放行需要：必要构建/静态检查/测试通过、最终 head 独立审查完成、阻塞关闭、人工同意。暂无自动合并/自动关闭白名单；身份、CI、分支规则和工具权限未配置并验证前不能以代理报告自动合并。GitHub 没有配置保护不是允许常规直推的理由；本次文档引导期按明确人工授权经 PR 放行，不豁免独立审查。

AGENTS、验证脚本、CI 和权限规则自身属于审查敏感改动，不由作者降低门槛自我放行。自动化审查未返回、限额或工具不可用时标记阻塞；不得用开发者再读一遍充当独立审查。常态保护配置列入后续治理任务，不伪称已经开启。

## 5. 问题闭环与责任

问题至少有异常表现、预期、必要证据、负责人；Codex 补充复现、原因、修复范围、回归与结果。无法复现、受阻或暂缓写清原因及补测安排，不标已修复。未经预先定义和配置的低风险自动关闭机制仍由人工放行；高风险/证据不足必须人工验收。

问题关闭不等于上线。不得降低验收标准、跳过必要测试、扩大权限，也不以“AI 生成”免除审核与交付责任。

## 6. 数据、环境与发布恢复

开发/测试/生产配置、账号和数据明确分开，调试入口、高权测试账号、模拟逻辑不得意外在生产启用。数据库结构、批量数据和关键配置用可追溯脚本，明确顺序、兼容影响、执行人及验证。

删除、批量修改、不可逆迁移或生产操作先确认影响范围、备份/恢复措施并取得指定负责人授权。权限仅限任务需要；不能通过更改检查规则绕过验证。

发布须说明负责人、提交或不可变构建产物、范围、依赖/部署顺序、验证、未解决风险、回退或替代恢复。测试与发布版本要可对应，发布过程中不夹带未验证改动。关键外部链路未真实验证时保持功能关闭或经批准的受控范围，并写启用条件。

发布后验证核心功能、日志、错误和指标，异常及时停止扩散并按方案恢复。涉及数据变更时确认新旧兼容，回退代码不等于恢复数据；不可直接回退须有前向修复/备份恢复方案。紧急修复需负责人授权、必要验证与恢复，并记录明确的补审补测期限和负责人，不能长期绕过流程。

## 7. 最小交付包与完成状态

交付包含任务/接口、差异范围、提交与环境、实际验证、未执行项、独立审查、已知风险、恢复方式和下一步。常规任务只有这些必要证据齐备才标完成。局部完成、模拟可用、待外部验证、待独立审查、已合并未发布分别展示。

当前本仓库仅有设计和轻量规范工具。检查命令以 AGENTS 为准；新增服务再补实际命令，不编造业务构建、运行、浏览器或 CMS/Redis 成绩。验证记录优先引用 PR/CI，避免把长日志塞进 AGENTS 和项目状态。
