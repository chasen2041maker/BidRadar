# 06｜Agent、记忆与证据匹配 v0.2

**Proposed｜2026-09-11。research 是一个业务微服务；微服务数量不等于 Agent 数量。**

## 1. 规则、模型、服务的分工

程序负责身份、来源状态、时间/币种、去重、权限、参数校验、预算、结果和副作用。模型负责语义理解、查询改写、选择有限只读工具、整理要求与解释差异。

六个服务不是六个聊天角色。首个研究工作流只需一个主编排器和确定性节点；新增专家 Agent 必须有评测收益，不把互相讨论当工程深度。

## 2. 研究流程

确认目标与权限 → 获取不可变输入 manifest → 规则筛选 → 检索证据 → 在预算内补充读取 → 按条件匹配 → 验证引用/数字/范围 → 有限修订 → 发布报告及未知项。

缺文件或服务不可用时返回 partial/waiting_input/failed 等明确状态。“足够证据”只指约定分析范围，不代表全部投标要求。模型调用次数、总时长和 Token/费用都有上限，具体值需基线与预算确认。

跨服务调用取固定版本。processing 后来生成新文档不能静默进入旧 manifest；通过明确补证步骤扩展 manifest 或创建新分析，记录变更原因。

## 3. 工具与拥有者

| 工具 | 调用服务 | 约束 |
| --- | --- | --- |
| search_catalog | catalog | 参数化过滤/检索，无任意 SQL，返回版本与索引滞后 |
| get_notice_bundle | catalog | 明确程序/标段/目录版本，保留各来源 |
| retrieve_evidence | catalog 搜索投影 + processing 原证据 | 索引候选必须回核原证据与授权，不只相信向量分数 |
| get_profile_snapshot | workspace | 服务端授权和指定版本，不自由查询其他团队 |
| compare_revisions | catalog + processing | 已确认版本关系，不按标题猜同项目 |
| request_document_fetch | ingestion | 已登记 source/asset 请求，返回异步状态，不接任意外网 URL |
| propose_profile_change | workspace 的待确认接口 | 仅提案，不直接改变确认事实 |

每工具有模式、超时、大小、可重试性、错误类别和证据格式；外部内容不能增添权限。服务调用身份、用户/后台委托和业务参数分开验证。

## 4. 上下文工程

按顺序装配安全约束、目标、授权与输入版本、必要企业事实、相关原文、有限历史、未决项。去重但保留否定、日期类型、金额口径、标段范围和 evidence_id。

token 超限减少低相关文本或明确缩范围，不把关键限制压掉后称完整。历史摘要保留来源且可过期；模型前次结论不变成新一轮原始事实。多源冲突同时保留，不总选更有利的一方。

## 5. 三种记忆的服务责任

| 记忆 | 权威服务 | 更新/失效 |
| --- | --- | --- |
| 执行与会话状态 | research | checkpoint 保存进度，恢复重新鉴权和检查预算 |
| 企业事实与偏好 | workspace | 人工确认、expected_version、有效期；变更事件使结果待复核 |
| 跟进与提醒 | tracking | watch/规则/变化历史；放弃理由不自动变成永久企业能力 |

LangGraph checkpoint 用于线程状态；长期业务数据不要求全部塞框架 store。[S5](12-source-register.md#s5) checkpoint 成功不证明报告已提交，发布有本地幂等账本。

用户说“可能有某资质”只能为未确认信息；“以后偏好远程”可产生待确认偏好变更。撤销或删除后，派生摘要/缓存/报告访问同步失效；事件只携带版本引用，不广播私有档案全文。

## 6. 条件匹配而非中标预测

先看来源/语种/类型/当前性，再逐项给 met/unmet/unknown/conflicting/not_applicable，最后做可解释相关性排序。硬条件、偏好和内容相关性分开。

不提供中标概率。若后续需要软维度评分，权重经用户校准且固定；未知不能直接算零或满分。可展示已知下界/含未知上界，但它只是规则区间，不是统计置信区间，更不能覆盖硬条件的 unknown。

默认输出为值得核查、存在明确冲突、资料待补充以及条件表。没有附件时不得说全部要求已读完。

## 7. 证据核验

程序验证 evidence_id 存在、属于 manifest、对应正确版本/标段、当前允许访问，数字/币种/日期能对上。语义核验检查片段是否支持陈述，关键要求由人工评测校准。

有限修订必须使用已登记证据；失败则 partial 或明确停止。引用可点击不等于语义正确；搜索分数高不等于覆盖全部要求。

## 8. 与 tracking 的协作

tracking 根据 CatalogRevisionPublished 定位受影响 watch，只有实质变化需要复核。AnalysisRequested 带委托范围、watch/rule 版本和目标版本；research 重新检查权限与幂等，拒绝过期/取消委托。

AnalysisCompleted 只说明研究结果可读取，不自动证明提醒已创建。tracking 独立保存 Inbox、复核终态和唯一提醒。格式变化可只记录，不触发昂贵的模型重跑。

## 9. 必测场景

文档提示注入；别的标段引用；企业资质未知；日期冲突；未支持语种；模型/工具超时；catalog 索引落后；旧 checkpoint 遇到撤权；分析中档案变更；背景跟踪取消但旧命令晚到；模型成功而消息发送失败。

程序守边界，评测查效果；不依赖一条“请准确”提示保证正确性。
