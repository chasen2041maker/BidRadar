# 24｜企业档案：最小建档与逐项补证

2026-09-12｜PRODUCT-001 后续确认。负责人已认可八类信息及渐进建档方向；本篇是产品字段设计，不是冻结的数据库/API schema，也不是某家公司的真实档案。

## 1. 确认范围

RQ-26：企业档案按八类组织，首用不强迫提交全套资料；能力事实、偏好、硬限制、证明和有效期分开。此项细化 [05 领域模型](05-domain-model.md) 的 profile_revision/assertion 与 [23 首批业务](23-first-market-rag.md) 的建档步骤。具体控件、枚举、必填规则和接口实现前仍需约定，不能由本表自动生成未审查的业务规则。

## 2. 八类信息

| 类别 | 最少记录什么 | 为什么需要／不能推断什么 |
| --- | --- | --- |
| 企业基本信息 | 名称或简称、所在城市；核查主体时再补正式名称及必要证明 | 标识档案，不按公司城市限定可接项目地区 |
| 接单项目类型 | 想接的软件定制、业务系统、网站/小程序、系统集成、AI应用，以及明确不接的类型 | 找候选；个人招聘、人员撮合不混作公司的开发项目 |
| 技术与交付能力 | 能交付的功能、技术栈、可负责的需求/前后端/测试/部署/维护环节 | 技术名词列表不证明能承担整套交付 |
| 交付与地域限制 | 远程、短期出差、驻场的接受程度、地点和限制 | 项目所在地、报名地点、开标方式和实际履约地点分开 |
| 相关案例 | 项目范围、本人/团队角色、交付内容、时间、可提供证明 | 做过类似系统不等于满足某公告规定的案例条件 |
| 资质与证明 | 名称、持有主体、有效期、用户确认情况、材料获取/核查情况 | 未提供证明不等于没有资质；证书存在不自动等于有效适用 |
| 人力与排期 | 可投入角色/人数、最早启动、持续投入、已知冲突及更新时间 | 历史能力不等于当前能按时交付；过期排期需重确认 |
| 商务偏好与限制 | 意向金额区间、付款安排、维保责任及其他用户明确限制 | 偏好用于排序，只有用户确认的硬限制才能作为相应排除依据 |

例如“某杭州软件团队做工单系统、可远程、短期出差需确认”仅为虚构输入示意。没有要求每家公司持有一套相同资质；遇到具体项目，以项目实际条款要求为准，不提供法律资格认证。

## 3. 首次只问四组问题

先让用户确认：公司叫什么；希望承接什么项目；目前能负责哪些工作；对交付方式有什么限制。不确定的内容明确保留待确认，不使用默认“是”或“否”填空。

案例、资质、人力排期和商务条件按具体项目补充。遇到公告要求案例时，系统指出缺少的是企业案例/证明；遇到项目附件拿不到时，指出缺少的是采购方材料。两种缺口分别处理，而不是让模型补造答案。

这是交互顺序建议：城市、技术栈、证书上传等不因此全部变成首屏硬性必填项。缺少必要判断依据时仍可发现候选，但报告只能给有限结论。

## 4. 每条信息要保留依据和版本

事实值与证明状态分离：用户明确有／明确没有／尚未确认是一维；证明尚未提供／已提供／不可读取／有效期待核查是另一维，不用一个布尔开关混在一起。

每条确认信息保留确认者、确认时间、适用主体、有效期或复核时间、证据引用、档案版本。权限和所属工作空间由服务端验证，不能信任任意传入的 workspace_id。企业材料归 workspace 的授权范围，不能放进公共招标索引或原创内容 CMS。

用户的临时说法先作待确认信息；正式变更形成新档案版本，既有报告保持原输入版本并可标记需复核。新分析重新读取当前授权范围内的指定快照；缓存命中不绕过撤权检查。沿用 [05](05-domain-model.md)、[06](06-agent-memory-matching.md) 的数据所有权与证据边界。

能力是能不能做，偏好是更愿意做，硬限制是不接受的条件。例如“优先远程”不能直接当“绝不驻场”；金额偏好不应抵消资质未知或明确的交付冲突。

## 5. 最小判断走查（均为虚构）

| 项目依据与企业信息 | 应当表达 |
| --- | --- |
| 公告要求知识库开发，企业确认有相关能力 | 技术相关；具体功能、工期等仍需单独核查 |
| 公告要求案例及证明，企业只确认做过、未提供证明 | 证据待补，不直接标全部满足 |
| 公告明确长期驻场，企业明确不接受 | 交付要求不匹配（unmet），不是证据冲突 |
| 公告要求某认证，企业尚未确认 | unknown，不等于没有认证 |
| 两份适用材料互相矛盾且尚无法确认效力关系 | conflicting，不能挑有利条款 |

以上是拟验收的产品行为，不是已运行的接口或 RAG 测试。已识别条件全部有支持也不代表已识别全部要求。具体输入/响应、空值、状态枚举、并发版本与迁移方案实施前写入对应契约，不把本篇替代接口文档。
