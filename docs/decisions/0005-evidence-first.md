# 0005. 证据优先，未知不当成满足

- 状态：已采纳
- 日期：2026-09-12（在 2026-10-01 的研究实现中落地）

## 背景

招标分析最危险的错误不是"漏掉一个机会"，而是"告诉用户满足条件，实际不满足"。模型写得很流畅，但可能没有依据。

## 决定

- 每条结论都必须引用原文片段，引用要能在本次研究的材料里找到。
- 结论只有五种状态：满足、不满足、未知、冲突、不适用。
- 缺证据、证明未核验、只是可能不满足，都算"未知"。**未知既不是满足，也不是不满足。**
- 企业档案是企业自己的声明，不是核验过的证明，所以资格类要求一律是"未知"。
- 几组常见的混淆要分清：
  - 技术相关不等于全部要求都满足。
  - 没填资质不等于没有资质。
  - 原文没写驻场不等于允许远程。
  - 交付期限不等于驻场时长。
- 报告冻结输入：之后档案或公告变了，旧报告不改，只标为"已过期"。

## 为什么

用户需要的是能核对的依据，而不是一个分数。宁可多标"未知"、列出待核查的缺口，也不能给出没有依据的判断。

## 代价

- 报告里"未知"会很多，看起来不够"智能"。
- 程序检查越来越严，模型输出受限，回答显得生硬（见 [研究 Agent](../agent.md) 的已知短板）。
