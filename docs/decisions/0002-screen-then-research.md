# 0002. 先筛选、再研究

- 状态：已采纳
- 日期：2026-09-15

## 背景

模型调用要花钱，也要时间。如果用户每打开、刷新一次列表都触发分析，成本会失控，而且大部分项目用户根本不感兴趣。

## 决定

- **筛选阶段**回答"哪些值得打开"：浏览、搜索、查看详情都只用规则和索引，不调模型。
- **研究阶段**回答"这个项目适不适合我们"：只有用户明确选择后才发起。
- 空选择不能代表"分析全部"。真要分析全部，也要先展示范围、数量和费用，确认后再提交。
- 跟踪、人工决定、自动复核授权三者分开；自动复核只有在用户明确授权、权限和额度都有效时才发起。

## 为什么

把花钱的步骤放在用户明确意图之后，成本可控，也避免"系统替用户做了判断"。

## 代价

- 用户多了一步确认操作。
- 当前实现里有一个"选择批次"的状态机（创建、确认、取消）。v2 改成点击"分析"时确认后直接创建任务，见[决策 0010](0010-upload-first-direct-analysis.md)。
