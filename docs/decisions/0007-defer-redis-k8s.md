# 0007. Redis 和 K8s 推迟到部署阶段

- 状态：已采纳
- 日期：2026-09-30

## 背景

最初计划在第一条跨服务业务链里就验证 Redis 和 K8s。实际做下来，数据获取、研究和跟踪本身的工作量已经很大。

## 决定

Redis（缓存、事件、限流）和 K8s 的运行验证，推迟到服务部署阶段。微服务、Redis、K8s、阿里云的方向保留。

## 为什么

在还没有可用业务流程的时候搭基础设施，只会多出一堆需要维护的空壳。

## 代价

- 当前的本地版本没有缓存，事件靠轮询数据库表实现。
- 部署相关的能力（扩容、故障恢复、监控）都还没有验证。
