# 0010. 招标文件上传作为研究主入口；点"分析"时直接创建任务

- 状态：已采纳
- 日期：2026-10-13

## 背景

- 资格、评分、技术参数大多只写在正式招标文件里，公告里通常没有。只拿公告做研究，结论里"未知"太多。
- 现在的工作台要先建一个"选择批次"，再确认、再研究。这套状态机多了两张表（selections、selection_history）和一组接口，用户也多走一步。

## 决定

1. **上传招标文件是研究的主要入口。** 用户上传自己合法获取的招标文件（PDF、Word），研究以它为主要材料。公开采集只负责发现有哪些项目。
2. **去掉"选择批次"。** 用户在公告详情页点"分析"时，页面先列出研究范围和预计费用，确认后直接创建研究任务。

[决策 0002](0002-screen-then-research.md) 的原则不变：浏览、搜索不调模型，只有用户明确确认后才花钱。变的只是确认的方式。

## 为什么

- 研究质量取决于材料。有了正式文件，抽取到的要求更全，"未知"更少。
- 一次确认就创建任务，少一套状态和两张表，用户也少一步。"确认前先看到费用"这一点照样保留。

## 代价

- 需要新增 documents 模块：上传、解析 PDF 和 Word、切片、检索（v2 阶段 3）。
- 上传的文件是公司私有数据，必须按公司隔离，存储和权限检查都要覆盖到。
- 一次分析多个项目的场景要另做：每个项目各自确认，或者以后再加批量确认。
