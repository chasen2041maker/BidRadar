# 0003. 租户数据隔离方式

- 状态：已采纳（设计已定，RLS 尚未实现）
- 日期：2026-09-14

## 背景

一套平台服务多家公司，各公司的档案、研究报告、跟进记录必须互相隔离。可选的方式有：每家公司一个数据库、每家公司一个 schema、共享表加公司 ID。

## 决定

- **按服务分库**：每个服务有自己的数据库。
- **库内共享表**：私有表都带 `workspace_id`，每次读写都用当前授权过滤。
- **行级安全（RLS）作为第二道防线**：即使代码漏写了过滤条件，数据库也会拦住。
- 不默认给每家公司单独建库。
- 公开采购资料可以服务多家公司；企业档案、分析、追问、跟进默认私有。

## 为什么

共享表的迁移和运维最简单。代价是必须严格做隔离，所以加 RLS 兜底，并用"两家公司互相访问"的负例测试来验证。

## 代价

- 单家公司的数据导出、删除、恢复更复杂。
- 应用账号不能是表的所有者或超级用户，迁移账号和运行账号要分开。
- 目前用 SQLite，RLS 还没实现；接入真实企业资料前必须完成并通过隔离测试。
