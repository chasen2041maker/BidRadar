# 07｜可靠性、安全、部署与成本

状态：Proposed。这里定义失败时必须如何表现，尚无运行证据。

## 1. 初始可靠任务：先只有一个事实来源

建议第一版以 PostgreSQL 持久任务为准：创建业务任务和必要事件在同一事务完成，提交后才向客户端确认接受。Worker 用短事务领取任务并记录租约/执行代次，随后释放数据库锁，再进行网络或模型调用。

`SKIP LOCKED` 可用于队列式多消费者避开已锁行，但它不是通用一致性读取方式，也不负责整个任务生命周期。[S6](12-source-register.md#s6) 不在数据库事务里等待模型几分钟。

初期不必同时引入第二套队列账本。后续 Redis 可以作为缓存，或只负责唤醒/传输；业务状态依旧落库。即使不使用 Redis 消息，也能通过多个 Worker 和故障测试学习实际并发可靠性。

## 2. 任务状态与取消

```text
queued → running → succeeded / partial / failed
             ↓
         retry_wait → running
             ↓
       waiting_input → queued

非终态收到取消请求 → 检查并持久化 → cancelled
```

图为允许路径概览；不是任何失败都自动重试。缺关键用户输入进入 waiting_input；暂时上游故障可 retry_wait；无访问权限、无效模式或超过预算应停止。

succeeded 表示分析范围按契约完成，仍可能有业务 unknown。partial 表示执行缺口影响成果，必须明确哪些步骤失败。用户关闭浏览器不自动取消；取消需要单独请求并保存。

取消与完成并发时，以事务中成功提交的状态转换为准：已完成的任务不能被伪装成从未执行。后续不得启动新的未授权动作；已发出的外部请求可能无法撤回，耗时和费用如实记录。

## 3. 租约、代次和结果发布

每次领取生成新的 attempt 与递增代次；心跳更新租约时校验当前代次。租约过期可接管，但旧 Worker 可能仍在运行。

结果发布必须原子校验：任务当前代次仍属于自己、状态允许发布、未被取消、输入快照与权限仍可用，然后写结果指针和内部事件。旧代次只能保存受控诊断信息，不能覆盖业务结果。

新资料或企业档案版本变化时，可保留旧快照结果用于历史查看，但不得更新“最新结果”指针为已经陈旧的分析。需要按当前版本重新排队。

这只能控制本系统结果发布；不能保证外部模型只计费一次，也不能靠代次撤回已经发出的第三方请求。

## 4. 幂等边界

| 操作 | 建议去重范围 | 结果 |
| --- | --- | --- |
| 同步条目 | 经核验的来源身份、表示形式与内容版本 | 重复原文不重复生成新商机 |
| 启动分析 | 工作空间 + 幂等键 + 请求体指纹 | 同键同请求返回已有任务，同键异请求报冲突 |
| 图节点结果发布 | task_id + 阶段 + 输入版本 | 恢复后不重复发布 |
| 应用内提醒 | 用户/关注规则版本 + 目标 + 变化指纹 + 类型 | DB 唯一约束下不重复创建 |
| 临期提醒 | 关注 + 具体截止类型/版本 + 提醒窗口 | 截止更新后旧计划失效，新计划可建立 |

事件与结果的持久化在适当事务内完成；外部队列发送失败不撤销已接受任务。采用 outbox 时，投递可能重复，消费者仍要幂等。定期对账数据库待处理任务，不能只相信一次唤醒消息。

## 5. 典型故障矩阵

| 故障 | 应有行为 | 必须验证 |
| --- | --- | --- |
| 数据库提交前 API 崩溃 | 未确认任务或安全重试 | 不伪造接受成功 |
| 已提交但响应丢失 | 用户以同键重试拿到同任务 | 任务和报告不成倍增加 |
| Worker 在模型返回后崩溃 | 恢复执行并检查阶段记录 | 可重复调用产生费用，但不能重复发布结果 |
| 旧 Worker 在接管后恢复 | 代次校验拒绝提交 | 新结果不被旧结果覆盖 |
| Redis 不可用 | DB 任务保留；缓存绕过受限或暂停 | 不无限打来源、不丢业务状态 |
| 图 checkpoint 与结果库不一致 | 从业务幂等记录核查 | 不将恢复节点视为未执行副作用 |
| 来源超时/429 | 有预算的退避与重试，标注资料陈旧 | 不生成虚假“没有新公告” |
| 截止日更正 | 重新计算对应标段计划 | 旧提醒计划不继续当最新发送 |
| 取消与完成并发 | 事务控制可解释终态 | 无取消后新发布或伪造撤回 |

## 6. 缓存设计

先缓存可重建的解析结果、确定范围检索结果和允许缓存的公开只读查询；不先缓存无版本的最终答案。

缓存键考虑 source/document/parse/index 版本、程序/标段范围、工作空间、权限版本、企业档案/偏好版本、查询指纹、模型或重排配置。公共原文解析可共享，但含私有资料的检索和报告不可共享。

TTL 只是兜底，不替代新版本和权限变更失效。撤销权限/删除资料后不能继续从旧缓存提供。缓存击穿需合并并发回源、限制总请求；Redis 故障时禁止无上限地把负载转移到来源或模型。

任务是否已经执行、提醒是否已发布必须查业务记录，不能依赖一个会过期的 Redis Key。

## 7. 身份、私有数据和模型边界

受控单人验证可在本机运行；一旦邀请多人试用，必须有服务端鉴权、空间隔离、下载授权和针对错误角色/缓存/向量/图状态的测试。不能把客户端传来的 tenant_id 直接当权限。

如果采用 RLS，检查实际应用角色、连接池事务上下文及后台 Worker 路径；表拥有者等角色可能绕过策略，必须按官方行为测试。[S7](12-source-register.md#s7)

企业资料发给外部模型前确认处理条件与用户同意；默认最小必要上下文，敏感字段脱敏。日志记录标识、状态、成本和错误类别，不默认上传完整档案、联系人、文档或提示词到第三方追踪平台。

## 8. 采集与文件威胁模型

外链是非可信输入。安全采集器限制允许域、协议和端口，校验 DNS/解析 IP、每次重定向及最终连接目的地，禁止 localhost、私网、链路本地和云元数据地址；模型不能改变允许列表。仅检查字符串域名不够。[S9](12-source-register.md#s9)

下载限制大小、耗时、重定向次数、媒体类型与解压大小；拒绝压缩炸弹、路径穿越；XML 禁外部实体，HTML 防脚本执行，文件处理最小权限且不带云凭据。不得执行附件宏或任意代码。

文档提示注入只能影响被分析数据，不能获得私有资料外传、任意 SQL/Shell、采购方联系或配置修改能力。攻击样本需进入评测。

## 9. 应用内提醒与外部通知

第一版只有应用内提醒，使用数据库唯一约束和已读状态保证体验。已生成但未显示的提醒可重试读取，不需要依赖邮件服务。

外部邮件后置：需明确订阅、身份验证、取消和接收方；维护 accepted/sent/unknown 等发送事实，不把服务商接受等同于送达。外部发送成功但响应丢失时核查或进入待确认，不盲目重复投递。任何个人邮箱的实际发送都需用户明确请求，不由本计划执行。

## 10. 部署演进与运维验收

**本地**：先在明确版本的环境运行数据库、API 和 Worker，端口默认仅本地暴露，不在 Git 中放密钥。

**Docker/CI**：锁定依赖，构建可复现镜像；CI 做静态检查、单元/集成测试与扫描。真实模型/外部 API 测试单独手动触发并受预算限制；来自不可信 PR 的代码不能读取密钥。数据库迁移前做兼容和备份检查。

**Kubernetes**：受控测试环境中将 API 和 Worker 分开，配置资源、服务身份、探针、优雅退出、并发上限和发布/回滚。先不自行搭高可用数据库、服务网格或多云体系。官方说明即便特定单实例 Job 配置同一程序仍可能启动两次，因此业务幂等不能交给编排器替代。[S8](12-source-register.md#s8)

API liveness 不绑定外部来源/模型可用性；readiness 与所需本地依赖按服务职责定义。Worker 退出停止领取，已有任务完成或由租约机制接管。扩容受数据库连接、上游配额和模型总预算约束，不以加副本解决所有问题。

交付证据包括：从干净环境启动、一次升级/回滚、终止 Worker 后恢复、备份实际还原、密钥更换、故障定位。kind 或受控云测试不称为长期生产运维经历。

## 11. 可观测性与费用

日志串联 request_id、task_id、attempt、source_id、document_version、profile_revision、trace_id；避免原文敏感数据与高基数业务 ID 直接做指标标签。

关注：同步滞后、隔离/解析失败、任务排队与终态、重试、陈旧报告、未知条件比例、引用错误、模型调用次数/Token、缓存命中、单任务耗时和费用、内部提醒去重。

预算公式：模型输入/输出费用 + 向量/重排费用 + 存储/网络 + 运行环境。价格和供应商未选择，不写虚构月成本；负责人先设单任务、每日、每月上限与超额行为，再进行真实调用。无预算授权不创建付费资源。
