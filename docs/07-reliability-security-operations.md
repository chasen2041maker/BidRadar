# 07｜微服务可靠性、安全与运行 v0.2

**Proposed｜2026-09-11。Redis、K8s 从首条运行链进入；本页没有实测结果。**

## 1. 本地事务，跨服务最终一致

每服务保存自己的业务状态、local_job、Outbox、Inbox 和事件日志。API 只有本地接受事务提交后才返回 202。网络/模型调用不占数据库长事务。

生产者在本地业务事务写 Outbox；relay 发送 Streams 后记录传输状态。消费者在本地事务写 Inbox + 业务变更或持久 job，再 ACK。ACK 前崩溃会重投；ACK 后 Worker 崩溃由本地任务恢复。传输至少一次、内部发布幂等，不宣称整个系统恰好一次。

长任务不在消费回调里一直持有消息直到模型结束。接收已持久化与实际完成有各自状态，UI 不能混同。

## 2. Redis 不能成为唯一恢复依据

redis-core 存 Streams/消费组及有限配额状态，noeviction、持久化和容量监控；redis-cache 存允许淘汰的可重建数据，独立实例/预算。[S19](12-source-register.md#s19)

Redis 故障时，业务接受可在本地队列预算内继续持久化并标排队；达到 backlog 上限返回可解释的限流/暂不可用。采集和模型配额检查不可用时暂停相关外部调用，不能绕过配额直接执行。缓存故障允许有界绕过，不允许无限回源。

**只重投未 sent 的 Outbox 不够。**消息可能已被 Redis 接受后丢失。生产者保留持久 event_log 与 producer/topic sequence；每消费者有处理水位和缺口记录；通过拥有者的受控 replay API/relay 重放，再用 Inbox 去重。日志保留窗口、消费滞后、清理前提和超窗全量重建必须形成契约。[事件契约](14-service-event-contracts.md)

不得仅用 MAXLEN 截断仍有消费者未处理的事件，然后声称有 AOF 就绝不丢。XAUTOCLAIM 能接管消费组待处理项，但不替代业务租约或恢复已从 Redis 丢失的数据。[S20](12-source-register.md#s20)

## 3. 本地任务租约和 fencing

Worker 用短事务领取本服务任务，保存 attempt_id/递增 epoch/lease_until，释放锁后执行；心跳只可续自己的当前代次。SKIP LOCKED 只用于适合队列的领取，不作为一般一致性查询。[S6](12-source-register.md#s6)

发布本地结果时，事务同时检查当前代次、允许终态、取消请求、输入指纹并写结果指针/事件。旧 Worker 恢复后不得覆盖新结果。外部模型可能重复计费，不承诺因此消除所有重复外部请求。

research 的 checkpoint 与业务发布不共用跨系统事务：恢复时核查发布幂等记录，不因图节点重跑而重复报告。processing 的重解析产生新版本，不覆盖已引用制品。

## 4. 状态、取消和权限竞态

任务状态：queued→running→succeeded/partial/failed；可经 retry_wait 或 waiting_input 返回可执行状态。succeeded 是流程完成，不等于所有条件 met。

取消是持久命令，不是关浏览器。取消和本地提交由事务序决定；已完成后不能伪称撤回。新外部调用开始前检查取消/委托/预算；已在途调用未必可停止，费用和暴露窗口如实记录。

跨服务撤权不具有全局原子性。私有读、报告下载和新模型调用前向 workspace 校验当前授权；授权服务不可用时拒绝/延后，不以旧投影放行。事件驱动清缓存用于收敛，不能当即时撤权的唯一措施。已经发出的外部上下文无法撤回；降低敏感内容、限制委托有效期，并明确这个边界。

## 5. 幂等与重放

| 操作 | 去重/并发依据 |
| --- | --- |
| 客户端分析命令 | 服务+workspace+Idempotency-Key；同键异 body 冲突 |
| 事件接收 | consumer+event_id，Inbox 和本地 job 原子保存 |
| 解析 | 原件+parser/rule 版本；新规则是新派生版本 |
| 目录关联 | 来源身份/明确引用+关联版本，禁止标题强合并 |
| 结果发布 | job/epoch/阶段/输入指纹与本地唯一约束 |
| 后台复核 | watch+rule+目标 revision+profile revision+策略版本 |
| 应用内提醒 | watch+rule+变化指纹+提醒类型；重放不重复 |

重放区分正常补投、历史投影重建和受控负载实验。历史重建默认不对用户发提醒；处理历史期间新事件需有切换水位，不能把实时事件漏掉。源删除/权限撤回 tombstone 也参与重放，防止复活已删除数据。

## 6. 乱序、缺口与版本

不同服务无全局事件序。每 producer/topic 有传输顺序，业务对象有独立版本；源公告的生效关系仍由来源语义确定。旧事件只补历史，不回退当前指针。

发现版本缺口，先调用 owning service 补版本/快照，不能拿后来一条事件猜完整状态。catalog 索引落后显示 indexed_revision/lag；research 发布旧快照只能是历史/陈旧报告，最新视图读取时再次核对。

## 7. 故障矩阵

| 故障 | 设计行为 | 验收 |
| --- | --- | --- |
| DB 成功但客户端响应丢失 | 同键重试取原任务 | 无重复任务 |
| DB 成功、Redis 失败 | Outbox 保留，积压可见 | 恢复后投递 |
| Redis 收到后掉电丢事件 | event_log+水位重放 | 包括已 sent 的消息 |
| 消费者入库后 ACK 丢失 | Inbox 去重 | 不重复副作用 |
| Worker 接管后旧进程恢复 | epoch 拒绝发布 | 新结果不被覆盖 |
| 某消费者停机/事件乱序 | 缺口与超窗告警，补投或快照重建 | 不静默跳过 |
| 源 429/验证页/失效附件 | 有限退避、隔离、陈旧标记 | 不造空结果或补造条件 |
| Redis 配额不可用 | 暂停受限外部调用 | 不扩散请求 |
| 撤权/取消与在途分析并发 | 当前访问拒绝，记录在途边界 | 不暴露旧私有报告 |
| parser OOM/恶意压缩包 | 受限 Worker 失败并隔离 | catalog/研究仍可读旧有效版本 |

## 8. 缓存和配额

缓存键包含 owner/source、document/catalog/parse/index 版本、query、模型/重排配置；私有结果还含 workspace/profile/preference/access 版本。TTL 是兜底，不是权限控制。

公共解析缓存可共享；企业资料、匹配、摘要不能跨空间共享。缓存命中仍检查访问权。并发回源合并、最大等待、超时和熔断有上限；Redis 锁只用于减少重复，不作为正确性或事实确认依据。

源限流按域/凭据全局计算，模型按 provider/模型/工作空间计算；多 Pod 不能各自享受完整配额。research 数据库保存费用账本与任务预算，Redis 只执行快速计数/预留；重启后先重建保守余额，不能立即重置免费额度。

## 9. 网络、文件和提示注入

ingestion 是外部网页出口。域名、协议、端口、DNS/IP、每次重定向和连接目标都需验证；禁内网、loopback、link-local、云元数据地址。仅字符串域名检查或仅 K8s NetworkPolicy 不能覆盖全部 SSRF。[S9](12-source-register.md#s9)

文件限制下载/解压大小、时间、CPU/内存；禁 XML 外部实体、路径穿越、脚本/宏执行。processing 容器不带模型密钥或管理权限。扫描文档先标不支持/待复核，OCR 单独准入。

网页中的指令不能让 Agent 改配置、提升权限、查别的企业、执行 Shell/SQL 或向外部提交资料。源、提示、工具参数、工具输出是不同信任层。

服务间验证工作负载身份与目标 audience，用户/后台委托另验；K8s ServiceAccount 名字本身不是 HTTP 鉴权。密钥不进 Git/镜像/日志；跨空间向量、缓存、事件、日志、checkpoint 和下载都有测试。

## 10. 发布与观测

K8s 基础从第一服务阶段验证，细节见 [15](15-kubernetes-capacity-plan.md)。每服务独立镜像、迁移、契约和回滚。数据库 schema 扩展→双读/迁移→切换→删除旧字段，不假定回滚旧镜像能撤销破坏性迁移。

trace_id/correlation_id 贯穿同步和异步；记录 job/attempt、源/版本、配置、错误类别、耗时和成本，不默认上传全文资料到追踪平台。指标不要把所有公告 ID 当 label。

仪表盘至少有每源新鲜度、质量隔离、事件消费滞后、未解决缺口、队列年龄、租约接管、索引滞后、引用/未知分布、模型 429、费用与缓存命中。没有告警处理手册的图表不算运行能力。

## 11. 备份与成本

每服务定义数据保留、事件重放窗口和 RPO/RTO；一组跨库备份不天然同刻一致，恢复时通过版本、事件和对账收敛。真实还原后检查孤立引用、重复提醒和数据撤回，不只看容器启动成功。

单任务/每日/月预算、模型处理条件、云资源上限未批准前不创建付费资源。原文、向量、日志、备份和网络单独计量。计划阈值和实际结果分开报告。
