# 08｜评测、清洗与微服务验收 v0.2

**Proposed｜2026-09-11。所有数量、阈值和实验均为待审计划，不是已完成成绩。**

## 1. 三种业务基线

B0 人工原文+核查表；B1 结构化/关键词规则+模板；B2 在相同数据上增加语义检索、有限 Agent 与记忆跟踪。

同输入版本、企业档案、观察截止时间和标签下配对比较。B2 不可用更新资料与 B1 的旧资料比较后把收益全归模型。微服务是明确工程目标，但某个 Agent 步骤是否保留仍靠业务收益。

## 2. 数据与环境证据分层

| 证据 | 能证明 | 不能证明 |
| --- | --- | --- |
| 官方文档/网页阅读 | 存在入口或观察到页面结构 | 本机连接器已成功 |
| 真实 raw 冻结样本 | 该样本获取、解析与业务语义 | 全市场覆盖 |
| 自然脏数据回归 | 已发现问题的处理 | 所有网站都一样脏 |
| injected 故障副本 | 指定异常和恢复行为 | 自然异常比例 |
| mock 模型/负载回放 | 平台吞吐、队列、幂等、扩容 | 真实模型质量、真实用户量 |
| 真实模型小批评测 | 当前配置在样本上的波动与费用 | 大规模真实服务 SLA |
| 受控试用 | 参与者的实际反馈 | 全行业商业价值 |

## 3. 样本规模和分组提案

每个准入来源先 50–100 条或该范围可得全部，人工核查 10 条；后续逐渐建设 100 个业务分析案例，先以 30–50 个启动。按公告族、跨源转载、变更与标段关系分组，不让同一项目跨开发/留出。

建议按完整项目组约 70% 开发、30% 留出，实际组数不足时调整并披露。不用后来的授标/更正补全历史输入。反复查留出结果后修改提示词视为污染，应换组。

来源多样性、格式、语言、活跃/历史、简单/困难分别抽样。至少一条真实网页和一条真实文件路径进入核心数据评测，不能所有标签都来自规整 API。

## 4. 标注和清洗质量

每案例标目标范围、证据、关键条件、金额口径、截止类型、原始表达、企业确认事实、正确状态和禁止结论。模型可辅助草拟，不能自写标签自判满分。

每条真实质量问题记录 source/native ID、raw hash、定位、原值、处理值、规则版本、影响、人工确认及 expected result。原数据正常而解析器丢字段要算实现缺陷。

质量报告按来源/格式分列：可得率、字段正确率、解析/部分/隔离数、身份合并 precision/recall、错合并数量、原文定位、规范化可重放一致性。未获取、争议和排除项有分母，不靠删难例抬指标。

## 5. Agent 与业务指标

已识别硬条件召回只针对当前实际资料可识别的标签；五状态输出报混淆矩阵；引用支持率和关键陈述证据覆盖分开；候选 Precision@K 与有界标注候选池召回分开；变更识别区分排版和实质；记录人工修改数、审核用时和采纳/纠正原因。

一个可点开 URL 不是正确引用。unknown 比例高可能是合理资料缺口，也可能是检索失败，要分类。不能报告中标概率或未定义的全能准确率。

## 6. 契约与微服务验收

独立构建发布每服务；测试只读拥有者 API 而非偷连数据库；测试 N/N-1 schema 兼容、缺字段、未知 enum、超时、重复事件、乱序、缺口与终态。

同一事件的不同业务消费者必须各自收到；同服务多个实例可共消费组分工。ACK 发生在本地持久接受后；模拟 ACK 丢失、Redis 发送后丢失、消费组丢失，必须能从 event_log/水位恢复。

私有 API、索引、缓存、日志、事件引用、后台委托、checkpoint 恢复和文件下载做跨空间与撤权测试。服务账号没有跨库权限；独立镜像不导入其他服务 ORM。

## 7. 阻断测试清单

| ID | 场景 | 通过行为 |
| --- | --- | --- |
| D01 | 重复/转载/多语言 | 不重复算商机，保留来源 |
| D02 | 多标段金额/日期 | 不串用总量、时间和范围 |
| D03 | 更正乱序/关系不明 | 不回退、不强合并 |
| D04 | Open 属采购方式 | 不识别成仍开放；历史授标/取消不进当前列表 |
| D05 | 日期/币种/字段缺失 | 保留原文和状态，不补造零或 UTC |
| D06 | HTML 结构变更/访问验证页 | 隔离或明确失败，不空表成功 |
| D07 | parser 规则更新重放 | 原件不变，新派生版本可追溯 |
| A01 | 资质没填/附件缺失 | unknown，不假定 met/unmet |
| A02 | 引用别标段/冲突证据 | 拒绝或降级并保留冲突 |
| A03 | 文档指令注入 | 不提升权限/外传/执行代码 |
| A04 | 服务/模型超时或预算尽 | 有界停止、可解释 partial |
| M01 | 档案/权限变化 | 旧结果陈旧或拒绝访问，不能沿旧缓存放行 |
| R01 | 提交响应丢失 | 同键同任务，异 body 冲突 |
| R02 | ACK 丢失与重复接收 | Inbox 去重，无重复业务发布 |
| R03 | Redis 已接收消息随后丢失 | 重放已 sent 事件，不只补未发 Outbox |
| R04 | 旧 Worker 恢复 | epoch 拒绝过期提交 |
| R05 | 新旧消费者兼容/缺口 | 兼容或隔离告警，不静默跳过 |
| T01 | 截止更正/重复变更 | 旧计划失效，内部提醒唯一 |
| T02 | 历史投影重建 | 默认不对用户重发历史提醒 |
| S01 | 跨库/跨空间/撤权 | 访问拒绝，返回最小错误信息 |
| S02 | 私网 URL/危险文件 | 受控拒绝，解析服务故障隔离 |
| K01 | NetworkPolicy 实际不生效 | 测试发现并阻止受控共享部署 |
| K02 | 单服务升级/回滚 | 消费者兼容，迁移有解释 |
| K03 | 扩副本 | 不放大源配额和模型预算 |
| P01 | 查询/清洗/分析分别加压 | 原始指标、错误/积压/成本与限制齐全 |

固定关键测试必须通过进入对应试用阶段，但通过不等于零风险。统计质量阈值在标签与基线后由负责人冻结，不先编 95% 成绩。

## 8. 容量测试纪律

详细负载见 [15](15-kubernetes-capacity-plan.md)。把在线列表/搜索、原件解析、消息消费和真实模型评测分开。报告虚拟用户、RPS、数据规模、长度分布、缓存冷暖、服务副本、硬件、模型模拟方式与时长。

高负载只访问自有 mock/回放环境；外部数据源仅做允许速率的有限验证。重复扩增十万条不能写成十万条独立真实招标，模拟一百用户不能写成已有一百用户。
