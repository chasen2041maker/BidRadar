# 08｜评测与验收：先定义怎样算对

状态：Proposed。本文所有数量、阈值与实验都是待审核计划，不是成绩。

## 1. 三种基线必须保留

B0：人工使用原始公告与固定核查表。

B1：相同数据、同一企业档案下的关键词/结构化规则筛选与固定报告模板。

B2：在 B1 可用后加入语义检索、有限 Agent 补证和持续跟踪。

对照保持资料版本、分析对象、截止观察时间和评价标准一致。B2 不得偷用更新文件与 B1 的历史版本比较，然后把改进都归给 Agent。只有 B2 相比简单流程带来可解释收益，才保留对应复杂性。

## 2. 三类测试结果分开报告

| 类型 | 能证明 | 不能证明 |
| --- | --- | --- |
| 固定返回值/离线重放 | 规则、状态、接口、恢复与已知场景行为 | 真实模型/来源服务一直正确 |
| 冻结证据 + 真实模型 | 当前模型配置下的语义行为、波动和费用 | 新数据分布与任意真实业务效果 |
| 实际来源 + 模型 + 界面 | 某时刻环境中端到端是否可用 | 全市场覆盖、商业价值或生产 SLA |

每份报告记录代码提交、配置、样本清单与来源许可、输入版本、时间、环境、模型可得标识、运行次数、成功/失败/缺失分母及测量方法。

## 3. 数据集建议与防泄漏

先取 100 条公告检查数据，其中至少 10 条人工逐字段核查；随后拟建设 50 个完整分析案例，每个包含真实来源证据、分析范围与经确认或明确标为合成的企业档案。

按采购程序及关联公告族分组划分，例如拟用 35 个开发案例与 15 个留出案例。**同一项目的旧公告、变更、多个标段和不同语言版本不能随机分到两边。**若 50 个案例不足以形成独立组，重新设定样本与比例并如实记录。

时间相关实验只使用当时已发布且允许获得的资料，不用后来的授标或更正答案补全早期输入。公开源现实变化不影响冻结样本，但需保留原件与许可边界。

合成边界案例可用于安全、并发和异常测试，必须单列，不能混成真实使用者反馈或真实商业项目采纳率。

## 4. 标注规范

每个案例标注目标程序/标段、真实可得资料、关键要求、条件类别与范围、正确证据、企业能力事实、条件状态、截止类型、未知项、可接受措辞和禁止结论。

至少由负责人人工标注；在邀请阶段争取业务使用者复核子集。模型可帮助草拟，不能由同一个模型生成答案再自己判满分。存在争议的标签标为争议或不纳入该指标分母，并披露数量。

留出集不用于日常调提示词/权重；一旦反复查看并据此修改，应承认污染，重新建立留出组。多模型测试记录尝试次数，不只报告最好的一次。

## 5. 指标定义

| 指标 | 定义/分母 | 注意 |
| --- | --- | --- |
| 字段正确率 | 人工检查正确的字段 / 被检查且有明确标签的字段 | 分类型报告金额、币种、日期、标段；缺失另计 |
| 已识别硬条件召回 | 正确识别且范围正确的关键条件 / 人工标注可从当前资料识别的关键条件 | 不声称覆盖未取得文件中的条件 |
| 五状态匹配质量 | met/unmet/unknown/conflicting/not_applicable 的混淆矩阵和每类指标 | 防止把 unknown 全变 met 或 unmet |
| 引用支持率 | 经审核真正支持陈述的引用 / 经审核引用 | URL 可点开不是通过 |
| 关键陈述证据覆盖 | 有适当证据的关键陈述 / 全部被审核关键陈述 | 只有引用支持率高可能仍遗漏引用 |
| 相关候选 Precision@K | Top K 中被标为值得核查的候选 / 实际展示数量 | K、筛选池和标签规范固定 |
| 候选召回 | 找到的相关候选 / 有完整标注的有限候选池中相关项 | 无法给整个互联网或 TED 未标全数据报召回 |
| 变更检测 | 在人工确认的变化中正确识别、范围与版本正确的比例 | 无关排版和真正条件变化分开 |
| 人工修改负担 | 需要改的字段/结论、是否漏关键条件、审核耗时 | 与人工/规则基线配对比较 |
| 运行表现 | 排队时间、处理耗时、P50/P95、成本、失败/重试率 | 小样本说明不稳定，按配置区分 |

N/A 不能随意排除难例以抬高结果。所有排除理由、未获取文件和无法判断项必须展示。

## 6. 阻断条件与质量目标分开

**阻断类测试**：固定关键场景必须全部通过才能进入对应试用阶段，包括权限泄露、伪造引用、重复发布、旧 Worker 覆盖、取消后非法提交、把已知关键日期混用等。通过只说明这些测试未发现问题，不证明零风险。

**统计质量目标**：关键条件召回、候选相关性、修改负担等先跑基线并检查标签，再由负责人冻结最低门槛及样本量。不在未测量时编造一个“95% 准确率”目标作为产品宣传。

目标一旦冻结，版本对比需在同一集合报告退步项；不能为通过临时降低门槛而不记录决策。

## 7. 最小验收场景矩阵

| ID | 场景 | 通过标准 |
| --- | --- | --- |
| D01 | 同公告重复导入 | 不新增重复商机或无意义提醒；重复计数可见 |
| D02 | 多标段不同金额/日期 | 不把总预算分配到每个标段，不串用日期 |
| D03 | 旧公告晚于新公告抓取 | 最新已知版本不因抓取顺序回退 |
| D04 | 变更引用不明 | 保留待关联，不自动覆盖 |
| D05 | 来源字段缺失/解析失败 | 保留不同缺失状态，不变 0/假日期 |
| A01 | 企业资质未填写 | 返回 unknown，不判定没有或具备 |
| A02 | 文件没有写远程 | 不输出支持远程 |
| A03 | 冲突证据 | 展示冲突及来源，不任选有利结论 |
| A04 | 文档提示注入 | 不增加权限、不外传私有信息 |
| A05 | 引用另一个标段 | 校验拒绝或明确降级 |
| A06 | 工具超时/预算耗尽 | 有限停止，保留可用结果和未决项 |
| M01 | 企业能力修正 | 生成新版本；旧报告标陈旧；不静默改历史 |
| M02 | 权限撤销后恢复图状态 | 拒绝读取原私有上下文与报告 |
| R01 | 请求响应丢失后同键重试 | 返回原任务；异请求同键冲突 |
| R02 | Worker 中断与接管 | 任务可恢复；旧代次无法发布 |
| R03 | Redis 不可用 | 业务任务不丢；来源/模型无无界回源 |
| R04 | 取消与提交并发 | 终态由明确事务规则决定，可审计 |
| T01 | 截止时间更正 | 旧提醒计划失效；新版本正确建立 |
| T02 | 同变更重复投递 | 应用内提醒只生成一次业务记录 |
| S01 | 跨工作空间查询/缓存/向量/下载 | 不能读到他人资料，也不泄露摘要 |
| S02 | 私网 URL/重定向/危险文件 | 采集器拒绝，不执行内容 |
| O01 | 升级、回滚和备份恢复 | 在声明的受控环境实际完成并保存记录 |

## 8. 对未覆盖能力保持诚实

首次 10 条人工核查不能证明整个数据源质量。50 个案例不能估计真实中标概率。单用户本地运行不能证明多租户安全。仅测试假模型不能证明真实服务有效。K8s 清单存在不能证明部署完成。
