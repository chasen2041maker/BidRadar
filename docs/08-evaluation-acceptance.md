# 08｜业务、Agent 与工程验收 v0.3

**Proposed｜2026-09-11。样本、阈值和实验是待审设计，不是已完成成绩。来源数量不再决定发布。**

## 1. 先验收产品行为

核心是档案→找项目→证据分析→追问→保存人工决定→跟踪变化。R0/R1/R2/R3 分别验收数据链、可用研究、持续使用和受控交付；不要求四源/六源/六大区。详细 BP01–BP10 用例见 [17](17-product-delivery-blueprint.md)。

一个来源能支撑完整用例即可进入研究验证；没有真实原文不能算通过。完整 v1 收口前补齐真实 HTML 和文件链，并保留自然问题的清洗回归；同一来源可提供不同形式。

## 2. 配对业务基线

B0：人工阅读原文+核查表。B1：结构化/关键词规则+模板。B2：同样资料上增加检索、有界 Agent、记忆及变化解释。

固定资料版本、企业档案、观察截止、问题和标签，记录输入范围；B2 不能用更新资料与 B1 的旧资料比较后把优势全归模型。先与简单规则相比，再决定哪项模型能力值得保留。

衡量关键条件漏项、引用支持、人工修改、审核用时、实际决定及成本。总词数、报告数、国家数和模型自评分不能替代业务成果。

## 3. 证据分层

| 材料 | 能证明 | 不能证明 |
| --- | --- | --- |
| 来源说明/网页阅读 | 有入口或已观察某种语义 | 连接器已成功 |
| 获准冻结原件 | 该样本内容、解析与引用 | 全市场覆盖 |
| 自然清洗回归 | 某真实问题被正确处理 | 所有数据都同样复杂 |
| injected 副本 | 指定异常的防御 | 自然错误比例 |
| mock 模型/扩增回放 | 指定平台状态和负载行为 | 真实模型质量、真实用户量 |
| 真实模型小批评测 | 当前配置在样本上的表现/波动/费用 | 大规模生产 SLA |
| 历史更正回放 | 变化复核机制 | 上游实时同步已连续验证 |
| 真实同步/受控试用 | 该时段覆盖和参与者反馈 | 全行业价值或完整实时覆盖 |

## 4. 样本与标注

先人工走查约 10 个代表项目作为种子，再逐步形成 30–50 个任务案例；必要时扩到100。数量是预算提案，不把小来源硬凑成固定配额。

按公告族、标段、转载和更正分组，建议约70%开发/30%留出并披露实际组数；同一采购过程不跨开发/留出。不用之后出现的授标或更正补全历史可知信息。反复用留出结果调提示词后视为污染，需替换组。

标签包括范围、证据、关键条件、金额/日期类型、企业事实、五状态与禁止结论。模型可草拟，人需理解并确认；不会的语言不得只用模型自评。记录难例、无法获取和争议，不悄悄删分母。

自然原始问题、解析器缺陷、注入异常和放大回放分开统计。版本、原件哈希、规则、前后结果、人工裁定均可追查。

## 5. 业务和模型指标

已识别硬条件的召回仅针对当前可得资料标签；五状态报混淆矩阵，尤其观察 unknown 被误判 met/unmet。引用支持率、关键陈述证据覆盖与可点击率分开。

候选 Precision@K 与有限标注池内召回分开，不报告不可验证的“全球召回率”。unknown 高可能是资料缺口，也可能是检索失败，须分类。

追问检查项目/标段/版本是否保持，事实与推断是否混淆；档案修改后检查旧结论陈旧；变化检测区分排版与实质。人工跟进决定不是资格真值，也不是训练标签自动反馈。

时间和成本包含必要等待、重试与人工修正；真实模型重复运行观察波动，不用单次成功宣称稳定。是否达到质量门槛需在基线后由负责人冻结。

## 6. 服务、权限与状态验收

每服务独立构建、迁移、发布，N/N-1契约、未知字段/枚举、版本缺口与失败均可测。账号禁止跨库；不共享其他服务ORM。

消息在本地Inbox+job持久接受后ACK；ACK丢失、Redis收到后丢消息、消费组丢失均须可恢复。不同业务订阅者有各自消费组；同服务多实例可以分工。

私有API、索引、缓存、日志、事件引用、后台委托、checkpoint恢复、文件下载都测试跨空间与撤权。最小单用户产品也用不同测试身份检验，不能等第二个真实用户出现才做隔离。

## 7. 固定阻断清单

| ID | 场景 | 通过行为 |
| --- | --- | --- |
| D01 | 重复/转载/多语言 | 保留来源，不重复算商机 |
| D02 | 多标段金额/日期 | 不串用总量、期限与范围 |
| D03 | 更正乱序/关系未知 | 不回退、不强关联 |
| D04 | Open是采购方式 | 不误判在招，历史/取消不进当前清单 |
| D05 | 日期/币种/字段缺失 | 保留原因，不补零或猜UTC |
| D06 | HTML变化/验证页 | 隔离或失败，不空表成功 |
| D07 | 规则升级重放 | 原件不变，派生版本可追溯 |
| A01 | 资质未填/附件缺失 | unknown，不假定满足或不满足 |
| A02 | 错标段引用/冲突 | 拒绝或降级并保留冲突 |
| A03 | 文档提示注入 | 不提权、不外传、不执行代码 |
| A04 | 模型/工具超时或费用不足 | 有界停止、状态与部分结果可解释 |
| A05 | 连续追问/刷新 | 不串项目/档案，已保存研究可恢复 |
| M01 | 档案或权限变化 | 旧报告陈旧/访问拒绝，不旧缓存放行 |
| R01 | 提交成功响应丢失 | 同键同任务，异body冲突 |
| R02 | ACK丢失/重复消费 | Inbox去重，不重复发布 |
| R03 | 已发送事件丢失 | 从event_log/水位恢复，不只补未发送Outbox |
| R04 | 旧Worker恢复 | epoch拒绝旧提交 |
| R05 | 版本不兼容/事件缺口 | 隔离告警或补齐，不静默跳过 |
| T01 | 截止更正/重复变更 | 旧计划失效，提醒唯一 |
| T02 | 历史投影重建 | 默认不重新提醒用户 |
| T03 | 人工决定与跟踪开关 | 分别持久，停止跟踪后不启动新的越界复核 |
| T04 | 关系不明或无新证据 | 保留待核查，不伪造变化 |
| S01 | 跨库/跨空间/撤权 | 拒绝，返回最小错误 |
| S02 | 私网URL/危险文件 | 受控拒绝和解析隔离 |
| K01 | NetworkPolicy未生效 | 实际测试发现并阻止共享试用 |
| K02 | 单服务升级/回滚 | 消费者兼容，数据迁移有恢复说明 |
| K03 | 扩副本 | 不放大来源配额与模型预算 |
| B01 | 费用临界与在途请求 | 保守预留、对账、暂停新可变任务，旧结果可读 |
| P01 | 查询/解析/研究分轨加压 | 原始指标、失败、拒绝、积压、环境与费用齐全 |

通过对应固定测试是进入相应试用阶段的前提，不意味着零风险。统计阈值尚未冻结，不预写95%或“生产零错误”。

## 8. 负载和交付证据

高负载只访问自有/获准回放环境；真实来源与模型只做允许速率和预算的小批验证。列清虚拟用户、RPS、记录/文档/块数量、文件分布、冷热缓存、节点/副本、硬件、模型模拟和时长。

单机多Pod不是多节点高可用；十万扩增记录不是十万真实商机。R3必须实际执行升级/回滚、备份还原与一次故障定位，不能以YAML存在代替。
