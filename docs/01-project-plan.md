# 01｜BidRadar 项目计划书 v0.3

**DESIGN_REVIEW｜2026-09-11｜项目优先、少源起步、完整业务交付。**

本稿描述目标系统，不代表已实现。最新要求、变更状态见 [11](11-decision-register.md)；产品行为见 [17](17-product-delivery-blueprint.md)。本轮整理既有决定及新的优先级，不重新宣称外部来源、岗位或云价格已经核验。

## 1. 一句话目的

帮助软件与 AI 服务团队找到值得进一步核查的公开采购项目，理解要求、比较企业能力、保存证据和未决问题，并持续跟踪变化。

直白地说：**不只帮公司看到一条公告，而是帮助它判断值不值得继续看、还缺什么资料、之后有哪些变化。**使用者负责投标资格确认和最终决定；系统不预测中标、不自动投标或联系采购方。

## 2. 本轮纠偏

前期来源可以少，优先完成项目。四源、六源、六大区不再成为研究、跟踪或上线的门槛。全球候选和扩展能力保留，但只在产品需求、证据缺口和预算允许时推进。

这不是放弃数据基础：没有可追溯原文和真实业务样本，Agent 不算完成；也不是退回单体：微服务、早期 Redis/K8s 和后续故障/压力实验继续保留。

产品价值尚未通过真实用户验证。需用相同资料比较人工、固定规则及 Agent 流程；如果某个模型步骤没有收益，缩小该步骤，而不是继续堆来源掩盖问题。

## 3. 已确认要求与实现提案

| 已确认要求 | 实现提案或仍待核验项 |
| --- | --- |
| 独立负责全链路，数据个人可得 | 一个主来源先打通，第二来源按需；不使用公司代码/数据/账号 |
| 优先项目，全球留作扩展 | 不设来源数量发布门槛，按业务缺口准入 |
| 微服务 | ingestion/processing/catalog/workspace/research/tracking 六服务提案 |
| Redis/K8s 从初期纳入 | 首个有业务的跨服务链就运行，不建六个空占位服务 |
| 数据清洗能力 | 保留原件、规则版本、质量隔离和真实网页/文件回归 |
| 阿里云部署 | ECS+K3s 低负载单节点候选，不承诺高可用 |
| 总预算约 100–200 元/月 | 计算、盘、网络、备份、模型统算，规格/报价待验证 |
| 明确排期 | 28 个有效周仍为容量提案，按产品里程碑重新分配 |
| 先审核再实现 | 本次仅文档，未批准编码/采集/采购/部署 |

框架、模型、首来源、机器地域/规格、费用分配和周工时仍未冻结。需求已确认不等于实现方案已经获批。

## 4. 首用户与首个使用场景

建议首用户为需要核查公开采购机会的软件/AI 服务团队业务人员，技术人员协助确认能力。首版先用经用户确认的一个企业档案，不需要企业真实内部系统集成才能使用。

典型任务：用户说明做什么、不做什么、已有何种证据；从当前覆盖范围找软件相关项目；阅读一份带要求与证据的分析；追问未决项；记录跟进或放弃；收藏后查看新的条件、截止或状态变化。

不默认用户有某国实体、当地资质、特定认证或远程交付资格。技术相关、硬条件、个人偏好与参与资格未知分别表达。

## 5. 完整产品闭环

```text
确认企业档案和偏好
        ↓
发现项目：相关性、状态、时间与覆盖范围
        ↓
看材料：正文、附件可得性、证据和缺口
        ↓
Agent 核查：要求—原文—企业证据—判断—待确认项
        ↓
多轮追问：保持项目、标段和输入版本
        ↓
人工决定：待核查 / 跟进 / 放弃，并保存理由
        ↓
收藏跟踪：出现实质变化后复核和应用内提醒
```

任务进度、取消、资料不足、预算暂停、模型失败和报告陈旧都属于正常产品设计。不能只实现成功路径。跟进决定与跟踪开关分开；放弃不能偷偷变成永久企业能力，停止跟踪不删除历史。

## 6. 功能优先级

| 优先级 | 交付内容 | 完成依据 |
| --- | --- | --- |
| P0 首个可用研究 | 登录/空间、确认档案、少量真实目录、原文定位、条件分析、追问、保存结果/决定 | 使用者能完成一次真实核查，并回到同一项目继续 |
| P1 完整 v1 | 收藏、变化复核、应用内提醒、档案修正、真实网页/文件清洗、预算控制、恢复与云端运行 | 持续使用、安全失败、可重建部署和可复查评测 |
| P2 按需扩展 | 第二及更多来源、更多地区/语种、更大负载、外部通知等 | 每项有用户需求或实际瓶颈、预算和独立验收 |

P0 不是粗糙无权限 Demo：真实数据、关键安全、幂等、基本恢复和费用约束从对应功能进入时就验证。P1 不是等待凑来源，P2 不阻塞 v1 完成。

## 7. 数据只按业务需要进入

建议先准入 1 个主来源，选源不按名气，而按软件/AI 项目相关性、当前状态可识别、原文可定位、标识稳定、变更线索、语言可评测及允许使用范围判断。TED 是已有候选，不是已批准或已接通的首源。

第一轮需要的内容是项目标识、公告类型和状态、服务范围、已知日期及类型、可得条件、正文依据、版本/获取时间、缺失与访问限制。预算和资质字段未披露时保留未知，不为了填满表造事实。

第二来源只补具体缺口。一个主源附带网页和文件也可以体现异构处理；同时按一个独立来源计数。完整交付保留至少一条真实网页和一条实际文件处理路径，但不要求在首个研究前全部齐备。

历史授标/取消用于关联、负例及变更回放，不充实活跃列表。暂无自然变化时可用已许可历史版本验证复核机制，必须标回放，不宣称已完成实时更新观察。详细规范见 [03](03-data-foundation.md)、[13](13-source-matrix-and-dirty-data.md)。

## 8. 架构和工程主线

| 服务 | 所有权和产品责任 |
| --- | --- |
| ingestion | 来源、同步、原件；给产品提供可说明新鲜度的资料 |
| processing | 文档版本、清洗和证据；处理失败能隔离与重跑 |
| catalog | 程序/标段关联、目录、索引；不把历史或重复记录推荐成新机会 |
| workspace | 成员、确认档案和偏好；私有信息的权限与版本权威 |
| research | 分析、上下文、报告与费用；把资料变成可核查结果 |
| tracking | 关注、人工跟进记录、变化复核与提醒；让产品持续有用 |

保持独立数据、接口、镜像和迁移，禁止跨服务共享 ORM 或直读写表。微服务数量不等于 Agent 数量；研究先用一个有界编排器和确定性节点。工具取受授权版本，模型不执行任意 SQL/Shell，不决定权限和账单上限。

Redis 用于事件、配额和缓存，事件与可淘汰缓存分进程；数据库保存本地事务、Outbox/Inbox 和恢复日志。ACK 不等于最终完成，允许重试但不重复发布内部结果。详见 [04](04-system-architecture.md)、[06](06-agent-memory-matching.md)、[07](07-reliability-security-operations.md)、[14](14-service-event-contracts.md)。

## 9. 阿里云与成本

微服务从首条运行链纳入 K8s；线上候选为单台 ECS+K3s、单副本低并发、分库 PostgreSQL、两个 Redis 进程与独立备份。4核8G/16G 均只是待报价和负载验证的比较档，不是已选套餐或足够资源的保证。

保留 Terraform 基础资源描述、Helm/Kustomize 二选一、CI/CD、探针、日志追踪、告警、回滚和还原的交付目标；不立即创建这些资源。模型按需分析，解析错峰，构建不抢占线上容量。

总预算约 100–200 元/月。固定费、可变费和储备分开；采购须包含地域、续费、首次现金、网络/模型使用条件及完整报价。预算告警和应用暂停都不是云厂商总账单硬封顶。[16](16-global-sources-cloud-budget.md)

## 10. 交付里程碑

| 阶段 | 验收对象，不以来源数量代替 |
| --- | --- |
| D0 设计审核 | 当前计划、产品契约、服务和预算可走查；未批准开发 |
| R0 数据与证据链 | 一个获准真实输入经采集→清洗→目录，Redis/K8s、重复导入和原文定位成立 |
| R1 可用研究 | 档案→发现→条件分析→追问→保存决定；配对基线和首轮用户检查 |
| R2 持续跟踪 | 真实或明确标回放的变化→影响范围→复核→唯一提醒；补齐网页/文件质量证据 |
| R3 受控交付 | 阿里云预算内运行、权限、升级、备份还原、故障/负载报告、英文交接 |
| R4 条件扩展 | 实际业务缺口驱动新增来源/地区/语种/容量；不是 v1 的必经门槛 |

原 28 周容量提案保留但顺序重排，R1 前不集中扩四源，R3 前不强制全球覆盖；见 [09](09-roadmap-ownership.md)。开始日期和可投入工时待确认。

## 11. 成功、停止与诚实边界

成功证据是使用者能核查、继续研究和跟踪；同样资料下对照人工/规则/Agent，记录关键条件漏项、引用支持、人工修改、时间和费用。页面能用、来源多、容器多都不单独构成成功。

没有原文、错把授标当在招、错用标段、私有泄露、重复提醒、无法恢复的已接受任务、超预算仍继续调用均是阻断问题。没有标签不报准确率，没有试用不称商业价值已证实，单机不称高可用。

暂不做自动投标、报价、群发联系、法律资格认证、完整 CRM、全行业全语种、移动端、服务网格、模型训练或多云平台。扩展机制存在不代表覆盖成果。

## 12. 本人职责与当前交付

本人亲写连接器/清洗、SQL与事务、工具/上下文/记忆、幂等恢复、缓存失效，以及一次实际部署排错和质量改进。AI 协助方案、解释和审查，不以生成行数代替掌握。
