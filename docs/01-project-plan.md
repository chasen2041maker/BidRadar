## 1. 一句话目的

帮助软件和AI服务公司，把公开采购项目变成**有依据、可追问、可复核的商机判断**。

目录筛选回答“哪些值得打开”；深度分析回答“这个项目到底适不适合我们”。不只给摘要或一个匹配分数，而是说明推荐理由、已知条件、未知信息、需要补的证据，以及项目变化后哪些判断失效。人工负责投标资格确认和最终决定，系统不预测中标、不自动投标、报价或联系采购方。

## 2. 已确认方向与不变的边界

首批是中国公开软件开发、业务系统和AI采购外包机会，中文优先、不限城市；软件公司和AI服务团队是客户，远程团队不被排除。一个有用主来源起步，第二来源按具体材料缺口进入，不恢复四源/六源/全球覆盖发布门槛。

微服务、首条有业务运行链纳入Redis/K8s、阿里云方向、中文CMS及缓存验证继续保留。六服务划分仍是提案，不先创建六个空服务。按服务分库，服务库内按workspace隔离并用RLS作附加防线；公司三角色和受限资料规则按26/27执行。

产品价值未通过真实用户验证。以同一资料对照人工、规则和Agent流程，记录漏项、引用支持、人工修改、耗时与费用；技术组件数量、模型数量和来源数量都不是竞争力证明。

## 4. 首用户和首个使用场景

企业业务人员确认“我们是谁、想接什么、能做什么、交付限制是什么”，技术人员协助补证；企业档案按24渐进完善。没填资质不是没有资质，技术相关不等于能履约，线上开标不等于远程交付。

用户查看来源明确的候选目录，打开原文/材料清单，明确选择项目或标段后请求深度分析；得到条件证据表、待确认问题和下一步建议，再追问并人工记录跟进或放弃。是否跟踪、是否允许后续自动复核分别控制。

## 5. 完整产品闭环与两阶段闸门

```text
确认企业档案和偏好
        ↓
获准来源采集 → 保存原件 → 清洗/目录投影
        ↓
阶段A：目录筛选（哪些值得打开？）
标题、类型、已知金额/日期、相关性、来源状态、材料缺口
        ↓
awaiting_decision：等待用户明确选择项目/标段
可看目录和已有材料；不占用分析Worker，不隐式调用模型
        ↓
确认选择 → 当前权限/输入许可/版本/额度校验
        ↓
持久化分析任务与幂等记录 → 返回任务ID
        ↓
阶段B：深度分析（这个项目到底适不适合我们？）
要求—采购原文—企业证据—五状态判断—待补信息
        ↓
同项目/标段/版本追问 → 保存报告 → 人工跟进/放弃
        ↓
独立开启跟踪 → 实质变化 → 标记旧结论待复核 → 提醒
        ↓
仅在有有效复核委托及额度时自动新建分析；否则请用户选择
```

`awaiting_decision`是企业候选选择批次/选择会话的业务状态，不是采集器一直挂起，也不是未创建的analysis_run已经处于运行状态。公共采集可按来源许可继续更新；用户选择绑定固定候选ID/版本，不使用会随分页/刷新变化的数组下标。归属和具体接口详见28，仍是待实现契约，不偷偷给已有任务枚举加一个状态。

空选择必须拒绝建任务；缺省值不能代表“分析全部”。明确“分析全部”也要先展示固定范围、数量和费用边界，经确认后按同一授权规则提交。重复确认返回原持久任务；同一幂等键但内容不同返回冲突。刷新/断网不建新任务，关闭页面不等于取消；取消须持久化并说明在途调用的限制。

## 6. 功能优先级

## 7. 数据源与开源复用

中国政府采购网作为国内首源验证对象，采购方官网和项目关联的地方采购/公共资源平台按需补证；海外来源仍是后续候选。CCGP的中央/地方/更正是同一来源下的栏目/类型，不夸大为三个独立来源。

本次直接复用 `bidding-ai-analyzer` MIT许可下的CCGP查询参数映射、列表选择器及元数据拆分思路，改成无网络副作用的小模块，保留上游SHA、版权和完整许可。没有复制其进程内任务字典、后台线程、空选择分析全部、固定每页20条、异常静默跳过等实现。详见 [28](28-two-stage-and-source-reuse.md) 和 [第三方记录](../third_party/README.md)。

其他项目的来源入口写入候选清单，不自动启用：可见网址不等于公开API、可复制代码不等于允许采集/转载数据、README的enabled=true不等于接口可用。来源许可、robots、访问条件、附件/登录/CA/付费、保存/展示/模型处理和限频分别核验。未获准不批量抓取，不绕过验证码、登录或付费控制。

首轮保留稳定身份、原始链接、公告类型、金额口径、日期角色、原件/解析版本、观察与获取时间、材料缺口。未知金额不填0；采集失败不当无商机；历史中标、采购意向与可能在招的公告分开展示。标题/列表只支撑初筛，不能证明全部要求已读。真实网页/实际文件路径和原公告/更正走查仍按03/13/25完成。

## 8. 工程与复用分工

| 所有者 | 责任 |
| --- | --- |
| ingestion | 来源准入、同步、原件、来源健康；本次仅CCGP离线适配，不建运行服务 |
| processing | 清洗、文档版本、证据片段、解析质量与隔离重跑 |
| catalog | 公共候选目录、程序/标段关联、索引、新鲜度，不保存公司选择和私有分析 |
| workspace | 当前成员、确认档案/偏好、企业候选选择会话；不越权写research任务表 |
| research | 受授权选择的持久任务、有限编排、报告、费用及输入快照 |
| tracking | 人工跟进、关注开关、变化影响、复核委托和唯一提醒 |

每服务独立数据、接口、镜像和迁移；跨服务引用通过版本契约，不跨库JOIN。研究先用一个主编排器和确定性节点，多Agent需评测收益。权限、配额和外部副作用由程序控制，不交给模型决定。

借鉴两阶段交互、条件清单、来源失败反馈和变化提醒，不整仓换底座，不引入特定行业模板中的硬编码判断，不把MCP评分当最终投标决定。CMS不与业务后台混同；redis-core与redis-cache分进程，缓存可重建、命中仍鉴权、撤下不复活。模型失败保留目录及已有有效报告，不能把未评分项目全部删除。

## 9. 云资源与成本

首条运行链纳入K8s；单台ECS+K3s、单副本、分库PostgreSQL和两个Redis进程是待测低负载候选，共机不是高可用。4核8G/16G仅为比较档，不是足够容量的结论。

总月预算约100–200元，固定费/可变费/储备分开，报价需包含地域、续费、首次现金、网络和模型使用条件、备份与存储。目录筛选默认走规则/目录索引，深度模型按明确选择执行；后续轻量模型排序也需独立验证和预算约定，不由本轮默认打开。模型费用告警不能保证云账单硬封顶。

Terraform、Helm/Kustomize二选一、CI/CD、探针、日志、告警、回滚和恢复保留为相应阶段目标，不在本轮创建云资源。

## 11. 成功、失败与验收

来源状态至少向用户区分本次请求成功、部分失败、全部失败/受限，并分别展示来源最近成功同步、实际检查时间、索引时间和报告分析时间。“请求来源全部成功”不是全国覆盖证明，“零匹配”不等于来源失败。来源过期、模型未运行和模型失败是不同维度。

报告逐项列要求、原文版本/位置、企业证据版本、met/unmet/unknown/conflicting/not_applicable、解释和待补问题；可点击引用仍需验证语义支持。材料不足不填假结论，旧报告遇更正不覆盖；只有实质变化影响有关判断，格式变化不自动重跑昂贵模型。

新增验收见28：列表刷新零模型调用、空选择不建任务、固定选择ID/版本、重复提交幂等、跨公司/只读/撤权拒绝、来源故障≠无结果、预算暂停、模型失败保留目录、版本变化提示复核、提醒去重。离线适配测试不等于这些跨服务验收已通过。

无原文、把历史授标列为在招、错用标段、泄露私有信息、丢失已接受任务、重复内部提醒、超预算仍调用都是阻断问题。没有标签不报准确率，没有试用不称商业价值已证实。

## 12. 当前交付与责任
