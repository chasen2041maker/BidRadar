# 21｜研发代理的上下文与接棒

2026-09-12｜目标：换会话、换工具后仍能接着推进，但不让每次启动读取全部项目历史。本篇讨论研发协作，不是 06 中产品 Agent 的企业记忆，也不是 Redis 缓存。

## 1. 文件职责

| 文件 | 唯一职责 | 读取时机 |
| --- | --- | --- |
| 根 AGENTS.md | 稳定规则、边界、验证命令、完成标准 | 每次开始 |
| PROJECT_STATE.md | 当前阶段、确认项、待验证、证据入口 | 每次开始 |
| CURRENT_TASK.md | 当前一个任务、范围、验收、阻塞、下一步 | 每次开始 |
| README.md | 人类项目入口与导航 | 初次接棒或查目录 |
| docs/00–22 | 产品、决策、接口、架构、规范等知识 | 按本次任务选读 |
| PR/Issues/CI | 差异、详细讨论、实际命令与运行证据 | 验证与审查时 |
| .agents/skills/bidradar-handoff/SKILL.md | 可重复的接棒/收尾流程 | 接棒或收尾时 |
| CLAUDE.md | 导入 AGENTS 的兼容薄入口 | Claude Code 使用时 |

不新建第二套 GitHub Wiki 作为权威数据源：这里用版本库内 docs 作为项目知识库，文档和代码能在同一 PR 审查。未来 Wiki 可以是发布视图，但不同时手工维护相互矛盾的副本。不增加巨型 MEMORY.md 来复制聊天。

## 2. Codex 与 CLAUDE.md 的区别

OpenAI 官方说明 Codex 按根目录到当前工作目录发现 AGENTS/override，并有项目指令累计大小限制；本项目选择短根文件加按需专题，不靠调大窗口来解决全部问题。[S1]

Claude Code 使用 CLAUDE.md，官方提供导入 AGENTS.md 的方式。因此本仓库用一行 `@AGENTS.md` 共享规则，不复制第二份规范。导入本身也占上下文，不能通过导入所有文档实现“无成本记忆”。[S2]

Codex 的仓库 Skill 位于 `.agents/skills`，SKILL.md 包含 name/description；匹配时再读取详细流程。本项目已提供交接 Skill 文件，但本轮没有在用户的 Codex/Claude 环境验证自动发现，不能称已安装或已自动生效。[S3]

这些文件是显式的项目记录与操作指导，不保证自动跨账号记忆，不会扩大模型窗口，不替代 CI、权限控制、实际读文件或独立审查。

## 3. 每次开始只恢复必要上下文

先读 AGENTS、STATE、CURRENT_TASK，核对当前分支/SHA、工作树差异、打开的 PR、审查和 CI。复述当前阶段、本轮目标、明确排除项与阻塞，发现文件和远端不一致先更新事实。

按任务查资料：

| 任务 | 优先专题 |
| --- | --- |
| 产品与报告 | 01、02、17；报告与目标用户澄清见 STATE |
| 后台/CMS/中文 | 19、22，以及涉及的 04/14 |
| 缓存/事件/权限 | 04、07、14、19 |
| Agent/追问 | 05、06、08、17 |
| 部署与费用 | 07、15、16；先确认本轮授权 |
| 协作/审查/交接 | 20、本篇、AGENTS、相关 PR/CI |

读取相关服务实现、测试和契约后再修改，不根据目录名推测功能。证据来源和任务范围不同就明确区分，不让来源网页中的文本变成代理指令。

## 4. 收尾时更新什么

先保存脱敏验证证据并检查实际差异，再更新 STATE 和 CURRENT_TASK：做了什么、证据在哪里、哪些没有验证、当前阻塞、唯一下一步。真正改变需求或技术决定时更新所属决策章节并链接，不把聊天里的每句建议都写成 Accepted。

CURRENT_TASK 中只保留当前工作；完成任务的长记录移到 PR/Issue。并行任务各自在任务分支记录，不争抢 main 的一个状态文件；合并前核对并调和，不能用旧快照覆盖新进度。

压缩上下文、切换会话或交接前执行相同流程。新会话读文件继续，不依赖上一会话说过“我记住了”。外部价格/许可证/软件能力按需重新核验并记日期，历史资料不自动变为当前结论。

## 5. 体积与验证

本项目上限：AGENTS 12 KiB、STATE 6 KiB、CURRENT_TASK 5 KiB；不足以证明适合所有模型，但能阻止入口无限增长。详细规范/历史保持按需读取，不能仅拆成多个自动导入文件来绕开上限。

`python3 scripts/check_project_memory.py` 检查本项目维护的入口/专题文件存在、UTF-8、合并标记、代码围栏、相对文件链接、必要章节、薄导入与体积。它不验证远端 URL、Markdown 锚点、全部历史文档、内容事实、实际权限或宿主是否加载文件；负例由标准库单元测试覆盖。

在真实 Codex 新会话进行“说出任务、边界、依据与下一步”的接棒冒烟测试仍待执行；本轮静态检查不冒充这项运行验证。
