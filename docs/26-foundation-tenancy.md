## 2. 不因存储方式改变的业务不变量

个人账号、公司空间、成员授权分开。公司报告归公司业务空间，创建者退出公司不自动删除报告；移除成员应在私有读取、下载和新模型调用前拒绝访问。保留作者/审计记录与个人信息保留政策另行协调，不能以保留历史为由忽略删除要求。

同一公共项目的原始公开材料，可以在已批准用途内服务多家公司；结合公司人力、案例或限制生成的分析、追问、跟进理由默认私有。公司内谁能读写仍要角色矩阵，不能把“属于同公司”当作所有成员都有全部权限。CMS管理员不因此获得企业数据访问权。

外发前检查当前授权、用途、必要字段、供应商处理与保留条件。没有相应授权就不发送私有原件；已发出的外部上下文不能保证瞬时撤回。测试使用脱敏或虚构档案，不用生产资料试探接口。

原件在获准保留期内不可覆盖；新的解析和公告更正各有依据/版本，旧报告冻结输入，当前视图显示陈旧或待复核。删除/撤权后应使相关在线访问、缓存、索引和重放失效；审计及备份边界明确记录。

## 3. 三条不同的隔离轴

**按服务分库**解决“哪个服务可以写哪些业务数据”；**按公司隔离**解决“A公司的数据不能被B公司读取”；**按实例/机器分开**涉及资源、运维和故障范围。三者不能互相当作已经完成的证明。

PostgreSQL一个服务器实例可以管理多个数据库；数据库不等于服务器，每个客户端连接只能直接访问所连数据库，数据库之间的访问控制仍需角色/连接权限配置。[S2] 同实例的逻辑独库仍共享计算、内存和故障环境，不能宣传为物理隔离或高可用。

| 方案 | 主要收益 | 要付出的代价与风险 |
| --- | --- | --- |
| 服务独立库，库内租户共享表（首版选定） | 统一迁移、较少数据库和连接池管理 | 必须严格鉴权、租户上下文、RLS/约束和两公司负例；单租户恢复更复杂 |
| 服务内每租户独立schema（未选） | 命名空间可分开 | 仍需权限、迁移与search_path管理；不是安全免费中间层，本轮不增加第三套方案 |
| 私有业务按服务×租户分独库（未来按需评估） | 数据边界更明确，逻辑单租户备份/迁移可能更方便 | 建库/凭据/连接路由、schema版本、批量升级和恢复都要自动化；同实例不隔离资源故障 |
| 个别租户专用实例/部署（未授权） | 可按明确要求分开资源与运行边界 | 成本、发布、监控和恢复复杂度更高；仍须应用鉴权，不能承诺天然安全 |

微软的多租户数据指南强调共享与专属存储各有适用条件，独库应配套自动化配置及schema管理。[S1] 该通用原则不是采用Azure，也不是本项目费用测算。

“给每家公司一个全业务数据库，让所有微服务随便读写”违背现有数据所有权。未来若批准租户独库，仍须为workspace/research/tracking等私有域保留各自凭据、迁移与写入边界；公共采集/解析/目录不因增加公司就复制一套。同一公司恢复时还要协调跨服务引用、对象存储和事件，恢复单库不等于整家公司状态恢复。

## 4. 已接受的首版方案与实施验证门槛

首版采用“按服务分库，私有表使用workspace_id和当前授权，数据库RLS作为附加防线”。从一开始明确稳定租户标识、导出/删除范围以及文件/缓存/检索作用域；物理数据库名不进入对外API。不先开发万能分片平台，不承诺以后拆独库零成本。选择该设计不是授权本轮建表或迁移。

实施前明确：服务端验证当前成员和租户上下文；每次请求/Worker任务绑定正确空间，连接归还后不可残留前租户上下文；遗漏上下文应拒绝，不能回落为全量查询；写入与对象关联也应检查空间一致。普通运行账号非表owner、非superuser且无BYPASSRLS，迁移身份与应用身份分开；RLS不是SQL注入防护或完整授权系统。[S3]

最低隔离实验覆盖：伪造workspace_id、读取另一公司的报告ID/附件、A到B复用连接、撤销成员后旧缓存/链接/任务、跨空间检索、后台Worker、单公司导出/删除与恢复。未通过不得接入真实企业资料，不以手写一个WHERE条件代替验证。实验输入使用两份虚构公司数据；验证读写与关联，不只验证列表为空。

若出现明确客户独库要求、独立恢复/删除目标、资源隔离或数据驻留条件，再比较专属库/实例，需要具体批准、自动化及容量依据。无论存储方式，缓存、下载、模型上下文和日志仍必须隔离；选错数据库连接也可能串租户。

未来迁移需逐服务租户清单、schema版本、数据与对象引用导出校验、写入暂停或变更追平、路由切换、事件/checkpoint/缓存处理、回滚与恢复验证。这些是保留的演进边界，不是已实现的自动迁移能力。

## 5. 任务、接口与试用门槛

分析先保存任务再返回编号，Worker执行不占用数据库长事务；重复请求按请求范围和幂等键处理，同键不同内容拒绝；浏览器断线不是取消。重试有限、取消持久化、旧Worker不能覆盖新结果；外部模型超时要保留调用/用量未知，不自动当作未计费。公司、任务和总预算上限的具体值在实验后审批。

每个接口在实现前记录：路径/方法、字段类型、必填与空值、金额类型/币种/精度、日期角色/时区/精度、状态转换、分页排序、错误/鉴权、幂等/并发版本和兼容迁移。模拟可用、真实可联调、业务验收分别记录。字段技术细节由Codex按现有规范处理；变更业务含义必须确认。

首版为受邀、受控试用，不以缩小用户量免除隔离。接入真实企业数据前批准保留/删除、备份范围、可接受数据损失窗口RPO及恢复时间RTO，并实际还原验证；目前无数值/SLA。主分支保护和required checks仍未配置，已有CI不等于服务器强制执行这些门槛。
