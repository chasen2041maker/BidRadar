# 路线图

更新：2026-10-13

## 现在在哪

本地版本的完整流程已经跑通：登录 → 企业档案 → 商机目录 → AI 研究 → 追问 → 跟进决定 → 关注 → 变化提醒 → 自动复核。全部代码已合并到 main。

| 部分 | 状态 |
| --- | --- |
| 数据采集 | 中国政府采购网、海南省公共资源交易平台：有限公开样本已跑通（12 条真实公告、1 份公开 PDF）。天津开放接口：代码已写，但平台仍拒绝开发者令牌 |
| 商机目录 | 可用：搜索、详情、版本历史、更正和结果公告的关联 |
| 工作台 | 可用：登录、三种角色、档案提议和确认、选择 |
| AI 研究 | 可用：5 个最终样本通过独立 AI 审查；样本太少，不能说明准确率 |
| 跟踪 | 可用：决定、关注、变化检测、站内提醒、自动复核 |
| 测试 | 旧代码 486 项，Python 3.10 和 3.12 均通过；v2 新代码 7 项 pytest 和 6 条分层契约 |
| v2 新代码 | 阶段 0 地基已完成：`bidradar/` 骨架、FastAPI、PostgreSQL、Alembic、分层规则检查、CI。还没有业务功能 |

### 还没有做

- 完整招标文件的获取和解析。目前只有公告片段，资格、评分、技术参数大多在招标文件里。
- 正式的用户系统、行级安全（RLS）。v2 已经接上 PostgreSQL，但还没有业务表。
- Redis、K8s、云端部署。
- 真实用户试用，以及人工标注的评测集。
- 持续自动采集：跟踪只处理已经导入目录的新数据，不会自己去网站上抓。

## 下一步：v2 改造

计划见 [v2 改造蓝图](v2-blueprint.md)。核心是三件事：

1. 先改成**模块化单体**，用 FastAPI + PostgreSQL，分层清楚；以后需要时再拆微服务。
2. 研究改成**抽取 → 匹配 → 核验**的流水线，每一步都能单独测试和评测。
3. 支持**上传招标文件**，作为研究的主要材料。

| 阶段 | 内容 | 完成标准 | 状态 |
| --- | --- | --- | --- |
| 0 地基 | 项目结构、FastAPI 骨架、PostgreSQL、迁移、CI | 健康检查能通，CI 通过 | 已完成（2026-10-13） |
| 1 身份与公司 | 登录、三种角色、档案版本，加 RLS | 两家公司互相看不到对方数据 | 下一步 |
| 2 商机与采集 | 迁移目录和采集适配器 | 现有 12 条真实公告能导入、能搜索 | 未开始 |
| 3 文档与切片 | 上传 PDF/Word、解析、切片 | 上传一份真实招标文件能看到带页码的切片 | 未开始 |

| 5 追问与跟踪 | 追问 Agent、跟踪、outbox 事件 | 变化后提醒只出现一次，授权后自动复核 | 未开始 |

### 阶段 0 做了什么

- `bidradar/` 目录按蓝图 3.1 节建好：`app/`、`modules/`（7 个模块，每个模块 6 个文件，目前只有说明）、`agent/`、`infra/`。
- FastAPI 应用和 `GET /health`：数据库连得上返回 200，连不上返回 503。
- `docker-compose.yml` 启动 PostgreSQL 16；Alembic 第一个迁移给每个模块建一个 schema。
- 6 条 import-linter 契约，对应蓝图 3.3 节的依赖规则。
- CI 新增 v2 任务：分层检查、迁移、pytest、启动 API 访问 `/health`。

怎么运行、每一层放什么，见 [开发指南](dev-guide.md#v2-新代码bidradar)。

### 阶段 1 怎么分工（建议，开工前确认）

按蓝图第 11 节：

- AI 写一个完整示例：登录。从接口、service、repo、表、迁移到测试全部打通。
- 负责人照着示例写同类功能：退出、成员管理、档案提议和确认。
- 负责人主写这一阶段的硬骨头：行级安全（RLS）。AI 只审查。

### 开工前要拍板的事

见蓝图第 13 节。已经确定的：

- 先做模块化单体（一份代码，API 和 Worker 两个进程），以后再拆微服务。
- 研究改成"抽取 → 匹配 → 核验"的流水线，不用 LangGraph。
- 技术栈：FastAPI + Pydantic、SQLAlchemy 2 + Alembic、PostgreSQL、Python 3.12、uv。
- 招标文件上传作为研究的主要入口，公开采集只负责发现项目（[决策 0010](decisions/0010-upload-first-direct-analysis.md)）。
- 去掉"选择批次"，改成点"分析"时确认范围和预计费用后直接创建任务（同上）。
- 分工按蓝图第 11 节：AI 写骨架和每个阶段的一个完整示例；同类功能和每阶段的硬骨头由负责人写，AI 只审查。

还没确定的：

- 前端是否暂时保留原生 JS（蓝图 13 节第 4 项）。阶段 6 之前定下来即可。
