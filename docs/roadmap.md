# 路线图

更新：2026-10-12

## 现在在哪

本地版本的完整流程已经跑通：登录 → 企业档案 → 商机目录 → AI 研究 → 追问 → 跟进决定 → 关注 → 变化提醒 → 自动复核。全部代码已合并到 main。

| 部分 | 状态 |
| --- | --- |
| 数据采集 | 中国政府采购网、海南省公共资源交易平台：有限公开样本已跑通（12 条真实公告、1 份公开 PDF）。天津开放接口：代码已写，但平台仍拒绝开发者令牌 |
| 商机目录 | 可用：搜索、详情、版本历史、更正和结果公告的关联 |
| 工作台 | 可用：登录、三种角色、档案提议和确认、选择 |
| AI 研究 | 可用：5 个最终样本通过独立 AI 审查；样本太少，不能说明准确率 |
| 跟踪 | 可用：决定、关注、变化检测、站内提醒、自动复核 |
| 测试 | 486 项，Python 3.10 和 3.12 均通过 |

### 还没有做

- 完整招标文件的获取和解析。目前只有公告片段，资格、评分、技术参数大多在招标文件里。
- 正式的用户系统、PostgreSQL、行级安全（RLS）。
- Redis、K8s、云端部署。
- 真实用户试用，以及人工标注的评测集。
- 持续自动采集：跟踪只处理已经导入目录的新数据，不会自己去网站上抓。

## 下一步：v2 改造

计划见 [v2 改造蓝图](v2-blueprint.md)。核心是三件事：

1. 先改成**模块化单体**，用 FastAPI + PostgreSQL，分层清楚；以后需要时再拆微服务。
2. 研究改成**抽取 → 匹配 → 核验**的流水线，每一步都能单独测试和评测。
3. 支持**上传招标文件**，作为研究的主要材料。

| 阶段 | 内容 | 完成标准 |
| --- | --- | --- |
| 0 地基 | 项目结构、FastAPI 骨架、PostgreSQL、迁移、CI | 健康检查能通，CI 通过 |
| 1 身份与公司 | 登录、三种角色、档案版本，加 RLS | 两家公司互相看不到对方数据 |
| 2 商机与采集 | 迁移目录和采集适配器 | 现有 12 条真实公告能导入、能搜索 |
| 3 文档与切片 | 上传 PDF/Word、解析、切片 | 上传一份真实招标文件能看到带页码的切片 |
| 4 研究流水线 | 五个步骤、任务队列、费用账本、评测 v0 | 评测用例跑通并出指标；Worker 中断后能续跑且不重复扣费 |
| 5 追问与跟踪 | 追问 Agent、跟踪、outbox 事件 | 变化后提醒只出现一次，授权后自动复核 |
| 6 收尾 | 前端改接新接口、删除旧代码、评测扩到 30 个 | 删掉旧代码后测试和评测都通过 |

### 开工前要拍板的事

见蓝图第 13 节。已经确定的：

- 先做模块化单体，以后再拆微服务。
- 研究改成流水线，不用 LangGraph。
- 技术栈用 FastAPI + PostgreSQL。

还没确定的：

- 招标文件上传作为主要研究入口。
- 去掉"选择批次"，改成点击"分析"时确认范围和费用。
- 分工方式（蓝图第 11 节）。
