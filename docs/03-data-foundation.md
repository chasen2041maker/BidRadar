# 03｜数据基础：来源、清洗与版本

状态：Proposed。**本文件没有真实 API 拉取结果，没有已确认的 TED 字段映射表。**下述字段名是内部设计名，不冒充官方 JSON/XML 字段。

## 1. 可行性证据的层级

| 层级 | 要证明什么 | 本次状态 |
| --- | --- | --- |
| 文档入口 | 官方提供公开查询接口 | 已读取：TED Search API，无需认证 [S1](12-source-register.md#s1) |
| 访问 | 负责人实际环境能否成功请求、分页、下载 | 未测 |
| 数据 | 所需字段、语种、正文与关联质量 | 未抽样 |
| 使用边界 | 采集、保存、模型处理、展示、再分发各自允许什么 | 完整复核未完成 [S2](12-source-register.md#s2) |
| 产品价值 | 这些资料足以帮助实际用户筛选吗 | 未验证 |

不能从第一行推导其余四行已通过。即使接口免认证，也不代表所有外链文件都可取或可以任意再分发。

## 2. 候选接入方案

首源：TED 已发布公告查询 `POST /v3/notices/search`，采用官方文档与接口描述确定参数、可返回字段和分页方式。[S1](12-source-register.md#s1)

原文优先级：来源提供的结构化 XML/HTML → 可直接下载且允许处理的文档 → 人工合法补充文件。支持格式与批量接口仍需实际验证；不依据旧示例硬编码所有下载规则。[S3](12-source-register.md#s3)

先限定近期范围与软件服务主题做样本，不全量抓取历史。CPV/地区查询如何覆盖目标行业需用样本校准，不把一个关键词或分类代码当成完整行业定义。

爬虫仅是按域审批的补充。遵守来源使用条件、适用访问政策和合理频率，不绕过验证码、登录或付费墙；robots 允许也不自动代表版权/数据使用授权。第三方附件单独登记边界。

## 3. 数据使用登记

每个来源记录：所有者、官方入口、访问方式、使用条款链接及复核时间、允许用途、原文保存/展示/再分发限制、个人信息字段、模型处理限制、抓取策略、撤回/删除策略。

本次法律声明页面出现访问验证，未取得完整正文。因此公开分发样本数据集、默认公开原始附件和将真实企业资料发给模型都不自动获批。代码许可与数据许可分别决策。公开仓库仅存文档、脱敏测试说明和经许可的小样本，不上传原始抓取仓库或联系方式集合。

## 4. 三层数据与对象边界

**Raw 原始层**：保存响应或文档原始字节、来源 URL、抓取时间、原始内容哈希、媒体类型、可见性、许可记录引用。清洗失败也保留可追查的元数据；哈希只能证明字节一致性，不能证明来源真实或内容正确。

**Normalized 规范层**：解析后公司/采购方标识、程序和标段引用、公告类别、各类日期、金额范围、语言、状态及来源定位。保留原文字符串和解析状态，不直接覆盖。

**Derived 派生层**：文本块、向量、抽取要求、匹配结果、差异摘要。每项绑定原文版本、解析器/索引/模型配置版本，支持重算，不充当原始事实。

原始层可用本地受控持久目录先验证，部署阶段再换对象存储；内容接口独立于具体供应商。

## 5. 增量同步的设计

一个同步任务记录查询指纹、时间窗、分页状态、开始/结束时间、成功数、重复数、隔离数、失败数和最后确认完成的水位。

若来源支持稳定分页/游标则按官方契约使用；若没有快照保证，以有重叠的时间窗口重复查询并做幂等入库。不可假设分页期间结果集合静止。历史补录与晚到变更需周期性回查，不只“取上次抓取时间之后”。

一次页面处理完成并持久化后才推进页进度；整个窗口可解释地完成后推进同步水位。未知模式或不可解析条目进入隔离区，保存原因而不是悄悄跳过。必须报告哪些记录未纳入结果。

429 遵守响应提示并有退避、抖动和总预算；临时网络故障有限重试；模式错误或无权限不无限重试。具体并发、速率和上限以官方限制及负责人验证为准，本稿不编造 API 配额。

## 6. 唯一性、语言与修订

拟用 `source + native_notice_id + native_revision + language + representation + content_hash` 描述原始制品身份；其中哪些字段实际可得、能否组成稳定键需 G1 证明。数据库内部另有自己的稳定 ID。

同一原生版本返回不同字节时不能直接覆盖，记录新制品与异常/补充语义。不同语言或 XML/HTML 只是不同表现形式，不自动产生不同商机。

公告到程序、程序到标段的关联优先依赖明确源标识或显式引用。只有标题相似不能自动合并。缺可靠标识时保存未关联公告，候选关联供人工确认；不能为了凑完整图谱强行链接。

旧公告晚到不应自动成为最新版本；更正可能局部影响某一标段或某个字段。无法解析更正语义时保留冲突并阻止全量覆盖。

## 7. 关键字段的质量规则

| 类别 | 保存内容 | 禁止行为 |
| --- | --- | --- |
| 金额 | 原始文本、Decimal、币种、金额类型、税/周期说明、作用标段 | 把估值、总预算、授标金额混用；跨币种直接加总；缺失变 0 |
| 日期 | 原始文本、截止类型、来源时区、精度、可确定的 UTC 值 | 把提问截止当投标截止；未知时区默认为 UTC；日期只有天时伪造精确秒 |
| 条件 | 原文、适用程序/标段、是否强制、解析状态 | 一个标段条件扩展到全部标段；推断作为原文 |
| 状态 | 已知状态、依据、观察时间、最新已知版本 | 抓取成功就标为可投；只看标题或日期断定所有资格 |
| 主体 | 来源标识、名称、地区与身份关系 | 仅同名就合并采购方或企业 |
| 语言 | 原文语言、处理语言、翻译版本 | 把译文包装成官方原文；不支持语种却给完整分析 |

缺失/解析失败/无法访问/不适用/相互冲突分开编码。候选状态示例：`missing`、`parse_error`、`inaccessible`、`not_applicable`、`conflicting`。

## 8. 截止时间和状态的保守策略

仅在公告类型、程序/标段关系、日期类型和有效来源明确时，进入“已知仍在接受提交”的候选状态；仍需展示核验范围，不据此确认某企业可参与。

取消/授标/结束等信息、多个截止日期冲突、日期未知都需独立展示。只有日期、没有时区/时间时，显示原始日期和不确定性，不能承诺精确倒计时。

没有最近成功同步，只能说明“截至某次同步所知”。来源中断期间提醒资料陈旧，不默默继续输出“最新”。

## 9. 文档解析与证据定位

优先原生文本和结构化解析。XML 禁用外部实体和远程模式加载；HTML 内容不作为可执行脚本展示；PDF 等处理在受限制进程完成并限制大小/耗时。扫描件不能提取时先标为暂不支持，OCR 仅作为后续按成本与准确性审核的例外。

证据位置保存文档版本与定位方式：XML 路径、HTML 章节/段落，或 PDF 页码/文本范围；引用展示时还能回到该版本，而非只回到会变动的首页。翻译内容同时关联原文。

采购联系人可能在公开文件中出现；不批量提取用于营销，默认不送入提示词、公开日志或评测数据。保留原件的合法性与保留期需单独审核。

## 10. G1 有限验证的建议验收

授权后建议选 100 条公告，覆盖不同类型、语言、多标段、缺失字段与变更，不只挑容易处理的样本；人工深入检查至少 10 条。建立真实源字段到内部字段的映射，记录路径、类型、缺失语义、样例 ID、检查人、模式版本。

报告必须包含：检索条件、拉取时间、分页完整性边界、原文可得率、语言覆盖、关键字段解析率、程序/标段/修订关联率、附件不可取原因、重复入库结果、模式失败样本和使用条件复核。

不把“拉了 100 条”当作数据源全部可行。若仅某子集成立，应冻结这个可支持子集，并把排除项写进产品页面。
