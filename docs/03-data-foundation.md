# 03｜多源数据基础：采集、清洗、隔离与版本 v0.2

**Proposed｜2026-09-11。尚未运行采集脚本，未建立真实 API 字段映射。**内部字段名不是任何来源的原生字段。

## 1. 数据目标与可行性层级

目标从两种异构输入逐步扩大到四个稳定来源、六个准入来源，并保留直接网页和原始文件处理。不是六个 API 地址，也不是把 TED 的 XML/HTML/PDF 算三个来源。

| 证据层级 | 要证明的事 | 当前 |
| --- | --- | --- |
| 官方入口/页面 | 确实有数据目录、接口说明或可见公告 | 部分已核验，见来源登记 |
| 运行访问 | 本机能请求、分页、下载；许可与频率可接受 | 未测 |
| 数据适用 | 业务字段、正文、版本、语种可支持特定用途 | 未抽样统计 |
| 正确接入 | 可重放、去重、清洗、隔离、追溯 | 未实现 |
| 用户价值 | 多源与 Agent 是否减少实际工作 | 未验证 |

网页可以读取不能推导其它四层通过。对 API、HTML、附件、模型处理、保存、公开展示分别审核。

## 3. 数据分层及服务所有权

**Raw 原始层由 ingestion 管理。**保存来源、获取时间、媒体类型、字节哈希、源 ID、请求窗口和许可记录；原始字节只写不可变对象。哈希证明字节身份，不证明内容正确。

**Normalized 规范层由 processing 管理。**把源表达映射为带原文和状态的字段、文档段落、证据位置；保留解析器版本、清洗规则版本、错误码、人工复核和隔离记录。它输出来源观察，不负责跨源强行认定同一个程序。

**Canonical 业务层由 catalog 管理。**按明确 ID、引用及可解释关联建立程序/标段/公告族；保留各源事实、冲突和关联依据。内部规范表示不是修改原始公告。

**Derived 派生层由所属服务管理。**catalog 的索引可重建；research 的要求解释、匹配报告和快照不是来源事实；tracking 的提醒不是官方状态。

每层输出通过契约与事件传播，不跨服务写库；补处理生成新的版本，不能覆盖旧证据。

## 4. 采集器不是万能网页代理

先使用合适的官方数据入口；需要原文和附件时做按域登记的定向采集。即使有 API，仍可在允许范围内保留原始网页用于证据和结构校验，不为制造困难而故意放弃稳定入口。

每个连接器定义 discover、fetch、checkpoint、source metadata，具体接口实现后冻结。连接器是 ingestion 内可扩展适配器，不是一源一个微服务。

登记访问政策、合理速率、robots、身份要求和再分发边界。robots 不等于版权许可。拒绝验证码/登录/付费墙绕过；受阻时保存原因与新鲜度，不把失败写成空数据。

SSRF 校验、重定向、媒体类型、解压限制与网络出口见可靠性文档。来源联系人不提取做营销，不进入默认提示词、公开日志或训练集。

## 5. 增量和文件快照

API：保存查询指纹、窗口、游标、原始页与条目处理状态。若来源不保证分页快照，使用重叠时间窗与周期回查，入库幂等；不假设“第一页到最后一页之间数据不变”。

CSV/XML 文件：每次是文件快照。内容哈希相同可跳过重解析，但保存观察时间；不同字节保留新的 raw_asset。不得把缺席于当天文件的项目直接认定已取消，须依据数据集范围和状态语义。

HTML：保存原文与页面级结构版本，按明确标题/表头/公告 ID 解析；页面返回访问验证或模板占位符应为获取/渲染失败，不是零条公告。历史内容和新公告共页时按章节与实体分开。

页面/文件成功保存不等于全部条目成功。同步水位只在窗口内条目已持久化或明确隔离且可追查时推进；质量报告必须列被隔离/未取得的范围。

## 6. “脏数据”分三种，不能混写成绩

**真实原始异常**：实际样本中的缺失、冲突、重复、表头/语义陷阱、失效链接。须记录原件、位置、发现时间和清洗前后。

**解析器错误**：原数据可能正常，但我们的抽取丢了标题、否定、表格结构。这是实现缺陷，不应归咎于网站数据脏。

**人工故障注入**：在授权副本上制造乱码、缺字段、时间错序、消息重复或损坏。用于可重复测试，显著标注 injected，不能说成自然缺陷率。

细化台账见 13 文档。禁止把同一干净数据删几个值后称“来自真实环境的脏数据集”。

## 7. 质量规则

| 类型 | 规则 | 禁止 |
| --- | --- | --- |
| 金额 | Decimal、币种、税/期间、估值/授标价、标段范围并存 | 缺失变零、跨币种相加、总预算复制给每标段 |
| 日期 | 原文、日期类型、时区、精度、可确定 UTC | 所有日期当投标截止；未知时区默认 UTC |
| 状态 | 页面章节、公告类型和字段语义联合判断 | Open 采购方式等于仍开放；授标资料当在招 |
| 文本 | 保留标题、段落、表头、列表、否定和单位 | 正则删掉否定词、脚注或适用范围 |
| 身份 | 源 ID 有命名空间，明确引用优先 | 标题近似就强合并；局部标段号全库唯一 |
| 重复 | 原件、发布、转载、翻译、修订分别判断 | 重复文件直接删除所有来源关系 |
| 语言 | 原文/译文、处理范围、翻译版本分开 | 未评测语种输出确定性完整分析 |
| 空值 | missing/parse_error/inaccessible/conflicting/not_applicable | 统一空字符串掩盖根因 |

标准化不等于纠正来源事实。发现疑似官方笔误时保留原文，记录候选纠正与人工依据，不默默改数值。

## 8. 质量隔离和人工处理

processing 将不可安全解析、未知模式、范围歧义等项目放 quarantine，记录 error_code、原件引用、解析器/规则版本、首次和最近失败、重试次数、责任阶段、复核状态。

可恢复解析失败与永久不支持分开。修规则后选择性重处理，输出新 document_version；catalog 依据新的可信规范观察发布修订，旧报告标陈旧。不能重新抓一遍覆盖旧原件来隐藏问题。

每次处理报告 input_total = normalized + partial + quarantined + skipped_known_duplicate 等互斥计数，详细定义后冻结，避免既算成功又算失败。

## 9. 原文定位与文件安全

XML 保留路径、命名空间和模式版本，禁外部实体；HTML 保留章节/表格/段落，展示时去执行能力；PDF 优先原生文本并保存页码/范围；Word 不运行宏。输入大小、解压总量、CPU/内存/耗时受限制。

扫描 PDF 无可靠文本时先标为 image_only/needs_review。OCR 作为有条件扩展，必须记录工具和置信限制、人工复核关键数字；不是所有文件默认 OCR，也不是本轮已完成工作。

## 10. 首批验证与指标

建议先验证 TED 和一个真实 HTML 来源，同时小样本查看 CanadaBuys/GLD；若网页许可未通过，可先用 CSV 完成运行链，但网页清洗目标保留并单独补齐。

每源拟抽 50–100 条或在范围内可得全部记录，人工核查 10 条；这不是当前完成数，也不强行要求小网站凑满。记录关键字段正确率、可得率、质量隔离、身份关联准确性、回放一致性与排除原因。

测试集按真实公告族和跨源已知关联分组；相同项目的转载、更正、标段不能跨训练/留出组。统计自然脏数据率必须以真实抽样为分母，不混入注入数据。

## 11. 使用、保留和撤回

每源登记采集、保存、模型处理、展示、再分发、个人数据、删除范围。TED 法律页本次受访问验证阻挡；其他数据目录的开放标记也不自动覆盖全部外链附件。准入完成前不公开原文全集。

公开仓库存代码和许可允许的小样本/元数据/规则，不存联系人全集、公司资料或未审文件。源撤回、许可变化、私有资料删除需在索引/缓存/报告与副本失效；备份到期边界说明，不能声称瞬时删除所有历史备份。
