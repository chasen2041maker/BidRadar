负责人已确认来源向全球扩展，计划部署阿里云，项目月度总预算约 **人民币 100–200 元**。微服务、Redis 和 Kubernetes 的目标不变。

**本轮为补充修订，不假称所有旧专题已经重写。**以下事项以 16 为准：全球范围替代原先固定六来源候选池；阿里云方向及总预算已明确；具体资源和地域仍未选择；28 周仍是原基准工作量假设，全球新增工作需按证据重估。其余 v0.2 服务/事件/权限/恢复设计继续保留。

## 已确认的工程方向

采用微服务；Redis 和 Kubernetes 从基础设计及首个可运行阶段纳入；后续增加数据量、并发和故障压力；制定排期；接入多个真实来源，包含网页、文件和真实脏数据，不只消费整洁 API。

v0.1 的模块化单体、Redis/K8s 后置及长期单源路线已被替代。预算有限不意味着退回单脚本，也不意味着六服务必须各买一台服务器。具体服务边界仍待审核，当前未批准开发或付费部署。

## 目标架构，不是当前实现

六个业务微服务提案：**ingestion 采集、processing 解析清洗、catalog 商机目录与检索、workspace 企业档案与权限、research Agent 研究、tracking 跟踪提醒。**每个服务独立镜像、迁移、数据库角色和契约；禁止跨服务直连业务表。

一个 Git 仓库不妨碍独立构建和发布。低并发云环境可评估单台 ECS + K3s，PostgreSQL 按服务分库/凭据，Redis 事件与缓存分进程。它们共用机器故障域，不能称多节点高可用。该布局须经过报价、网络、资源和备份验证，不能据此承诺 200 元已足够。

## 全球覆盖怎样证明

分别展示来源所在地区、实际涉及国家/地区、语言、公告类型、覆盖时间窗、最近成功同步、质量问题与支持级别。全球数据接入不等于全球可投标，不等于全量、实时、全语种分析。

欧洲 TED、北美 SAM/CanadaBuys、亚洲香港公开来源、南美厄瓜多尔 SERCOP、非洲南非 eTenders、大洋洲 AusTender 构成代表性候选。接口文档可读不等于实际接通；SAM 要 Key，AusTender 已核实 API 面向合同公告，南非 API 路径本轮失败而网页可读，CanadaBuys 本轮重读遭遇 403。详情及补充候选见 16。

首先打通两种真实异构输入，再逐项扩展。保存历史授标/取消样本，但不能放进活跃商机清单；不同格式不重复计为新来源。

## 计划中的业务闭环

发现公开公告 → 留存原件 → 清洗与质量隔离 → 关联程序/标段/版本 → 检索并匹配企业能力 → 带证据的人工初筛 → 收藏与记忆 → 变化复核和应用内提醒。

低成本运行优先规则筛选、增量同步、内容去重、按需解析与模型分析，不把每条全球公告都送给模型。系统不保证参与资格或中标，不自动投标、报价、联系采购方，不把未知当满足或不满足。
