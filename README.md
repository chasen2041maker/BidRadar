## 当前重点：项目优先，数据源服务于业务

负责人最新确认：**前期数据源可以少，优先做完整项目；全球扩源保留为后续方向，不以来源数量推动开发。**

第一条业务链建议由 **1 个经过准入、能够支撑业务的主来源**开始；第二来源只有在补充材料、验证重要差异或满足用户需求时加入。一个来源可以包含 API、网页和附件，但不能据此算多个独立来源。真实网页/文件清洗仍保留在完整交付中，不再要求先凑齐输入格式才开始 Agent。

v0.2/v0.2.1 的“四源才能交付研究、六源或六大区才能完成阶段”不再是验收条件。全球候选池保留作资料，不是当前待开发清单。**减少前期来源，不是改回单体、不做清洗，也不是降低证据质量。**

## 第一条需要做成的业务闭环

建立并确认企业档案 → 发现相关项目 → 查看原文与材料缺口 → Agent 分析条件和证据 → 在同一项目内继续追问 → 人工记录跟进/放弃及原因 → 收藏后跟踪变化 → 复核并生成应用内提醒。

任务失败、资料不足、预算暂停、旧报告陈旧、停止跟踪都要有真实状态，不能只演示成功截图。产品不保证投标资格或中标，不自动投标、报价或联系采购方。

## 架构与部署提案

六个业务服务：**ingestion、processing、catalog、workspace、research、tracking**。一个代码仓库；每服务独立镜像、迁移、数据角色和契约，禁止跨服务直读写表。六个服务不是六个聊天 Agent。

阿里云单台 ECS + K3s 为低负载候选布局，PostgreSQL 按服务分库/凭据，Redis 事件与缓存分进程；保持服务边界但共享机器故障域，不称多节点高可用。规格和报价必须验证，预算不是购买授权或配置可行性证明。
