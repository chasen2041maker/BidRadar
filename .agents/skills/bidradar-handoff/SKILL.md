# BidRadar 接棒、贡献者学习与记忆更新

遵守根 AGENTS、当前用户授权与工具权限。已存在此 Skill 的地方直接更新，不再复制同名技能或整份聊天。匹配后执行具体步骤，不能只说“已调用”。

## 触发与顺序

接棒/继续、获得有效新决定、完成一个小改动或复现失败、用户反馈已阅读/修改/运行、提交前、PR 更新/合并收尾、上下文压缩或会话切换，都检查是否需要更新。纯问答或无有效变化不凑笔记；只读范围不得自行写入。

1. 每次新任务、接棒或独立子任务先实际读取 AGENTS.md，含“基础决策：每次代理执行必读”章节；回报基线SHA与本任务适用约束。不得仅用旧摘要或把Skill未匹配当作跳过理由。
2. 读 PROJECT_STATE.md、CURRENT_TASK.md。
3. 核对真实分支、HEAD、工作树、PR、CI 和独立审查。Git 查询为 `git status --short --branch`、`git rev-parse HEAD`、`git diff --stat`；连接器环境读取等价远端信息。每项没查到就标未知，不依赖上次聊天中的旧状态。
4. 只读本任务相关专题、实现和测试，按 docs/21 的导航找资料，不全量导入历史。需要历史时读 docs/learning/INDEX.md 指向的单个任务笔记。
5. 简述本轮目标、排除范围和证据缺口，再推进已有授权的任务。

本轮基础确认和待定项详见 docs/26-foundation-tenancy.md；涉及租户存储、资料外发、任务或接口时按需读取。D-TENANCY-01未批准前，不将共享库或按公司独库写成既定实现。实际宿主加载未经验证时明确标注；任务分支规则未合并不宣称main生效。

## 边做边教

关键代码写中文注释/docstring，解释真实问题、输入输出、调用链、为什么这样做、权限/状态/版本/失败边界，不给每行语法配翻译。修改逻辑时同步注释；自测也注明关键断言在防什么错误。

每个小任务提供 1–3 个文件+函数阅读顺序、一条数据流、对应测试、一个失败例和一个适合负责人亲自尝试的小修改。负责人未确认前记录“待阅读/待实践”，不能从 AI 实现或 CI 通过推断本人已掌握；明确留给负责人的练习不要擅自代做。未授权的练习不自动执行。

## 有用记忆写到哪里

- AGENTS：稳定规则；PROJECT_STATE：当前事实/确认项/证据/待验证；CURRENT_TASK：当前一项工作和下一步。
- docs/learning/<任务编号>.md：当前任务的实现理由、阅读顺序、失败/验证和个人参与。沿用同一任务文件持续更新，不为每次小修复新造文件。
- 产品决定继续写所属专题/决策登记并链接；日志、请求、SHA 和独立审查明细留 PR/CI。只收集可核对证据、用户明确决定、复用价值高的坑；不要把 AI 推测变成事实。

笔记格式与示例见 docs/learning/README.md。状态无变化就不改时间戳；需求被替代要保留指向旧记录的链接。不得记录公司原文、密钥、企业私有数据或无价值聊天碎片。个人学习状态只根据负责人反馈或明确证据变更。

## 提交前的确定性检查

在仓库根目录：

```bash
python3 scripts/refresh_project_memory.py --write
python3 scripts/refresh_project_memory.py --check
python3 scripts/check_project_memory.py
python3 -m unittest discover -s tests -p 'test_*.py' -v
```

`--write` 只重建学习索引，不替你写业务判断；`--check` 发现状态或源笔记改变而索引未刷新；提交后加 `--base <完整SHA>` 检查差异是否遗漏任务笔记。该检查只覆盖已提交差异，源码注释质量和记录真实性仍需独立审查，不用改检查器的方式绕过缺项。

查看实际 diff，无关重构不混入。验证记录绑定最终 head 和环境；实质变化后重测重审。满足规则且有对应人工放行才通过 PR 合并，不直接推送 main。没有授权/审查结果时停在 PR，记忆自动化不豁免这些条件。

## 自动化与合并后核对

GitHub Actions 对分支 push、PR 更新运行检查并生成准确 SHA 的运行摘要；新分支无 before SHA 时差异防漏记留到 PR，不能声称基线比较已执行。

main push 额外运行固定状态页发布任务：只用 issues:write 更新 Issue #4，不写仓库代码。检查当前 main SHA、固定页标记和开启状态；串行发布防并行覆盖，过时任务跳过。关闭该 Issue 会阻止自动覆盖，不会自动重开。此页只是当前提交观察快照，源笔记仍随 Git 保留。

合并后回读实际 merge SHA、CI 和状态页是否刷新；失败/跳过明确记录。下一次接棒据此更新语义状态，不让合并动作猜“产品完成”或“本人已学会”。笔记和索引可立即更新，独立审查/合并/新 CI 结果后出现时放 PR 与实时页，不为写入自身 SHA 发起无限补丁提交。

## 交付给负责人的最小内容

本次做了什么、真实提交/验证边界、从哪个函数开始读、一个需要理解的问题及未代做的小练习。已读/已运行等进度必须有依据。不要每轮倾倒完整课程或架构清单。

## 触发验证及限制

验收提示：`继续 BidRadar`、`这个修复好了，提交`、`合并后更新状态`、`我刚读完函数并跑了测试` 应触发；`仅解释，不修改仓库` 只读。脚本单测不证明这些自然语言触发已在负责人机器通过，须独立记录真实宿主验证。

配置允许隐式调用不等于守护进程；宿主未发现技能时实际读取本文件并遵循，不假装自动加载。官方依据（2026-09-12 核对）：https://developers.openai.com/codex/skills ，明确描述匹配/显式调用、.agents/skills 与 allow_implicit_invocation。GitHub 事件机制见 https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows 。
